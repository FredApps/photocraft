## Pinned upstream reproduction and regression specification

Closes #7672.

`image.adjustments.selectiveColor` takes a range two ways, and `adjust_cmds::selective_from_params` reads both:

```jsonc
{"reds": [35, 0, 0, 0]}                  // the array form: c, m, y, k
{"colors": "reds", "cyan": 35}           // the scalar form: one range, the channels it changes
```

`selective_to` only looked for the arrays. A step recorded in the scalar form exported with an empty `ClrC` list — a Selective Color adjustment that changes nothing — and `skipped` was empty, so nothing said the values had gone. The report measures it on one red pixel: `[0.6509804, 0, 0, 1]` run directly, `[1, 0, 0, 1]` after export and replay.

### What changed

`selective_to` now builds the rows the way the command does: the arrays first, then the scalar form over the range it names, so a step that gives both (`"reds": [...]` plus `"colors": "reds", "cyan": 35`) exports what playing it would produce. An unknown range in `"colors"` cannot be written and refuses the step, as before.

### Tests

`a_selective_color_step_in_the_scalar_form_keeps_its_values` — the reported step round-trips to `reds: [35, 0, 0, 0]` with `method: "absolute"`; the scalar form over an array keeps both; and the array-only form is unchanged. On `main` the first assertion reads an empty adjustment.
