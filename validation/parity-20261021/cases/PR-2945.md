## What changed

PhotoCraft opens **GIMP XCF** files (`.xcf`, `.xcf.gz`), read only, through a new reader in `photocraft-io` (`crates/io/src/xcf.rs`, about 1,000 lines) written from the [public XCF specification](https://developer.gimp.org/core/standards/xcf/) and from files GIMP 3.2 writes; no GIMP code. Save suggests `.pcraft`; exporting as `.xcf` fails with a message, as PDN does.

- **Read:** XCF versions 0 to 26 (32-bit pointers up to 10, 64-bit after; newer files open with a note); uncompressed, RLE and zlib tiles; 8/16/32-bit integer and 16/32/64-bit float precisions (32-bit integer opens as 16-bit, floats as 32-bit float with HDR values kept; linear-light precisions get a linear sRGB or linear gray profile); RGB and grayscale as such, indexed through its colour map as RGB.
- **Layers:** any size and position (off-canvas too), opaque layers as locked-transparency layers, groups rebuilt from `PROP_ITEM_PATH` (nested, Pass through), names, opacity (`FLOAT_OPACITY` over `OPACITY`), visibility, offsets, layer masks applied or disabled, lock alpha/content/position, colour tags, GIMPhoto's `gimphoto-clipped` parasite as a clipping mask.
- **Blend modes:** the 2.10 set and the legacy set mapped to Photoshop's; Addition → Linear Dodge, Dodge/Burn → Color Dodge/Burn, HSV/LCH/luma modes to the HSL-based ones with a note, and the seven with no counterpart (Behind, Grain extract/merge, Color erase, Erase, Merge, Split) as Normal with a note naming the layer.
- **Image:** ICC profile (`icc-profile` parasite), resolution, guides, the comment (as document text metadata), extra channels as alpha channels, the saved selection as the selection.
- **Reported, not applied:** GIMP 3 layer effects (the layer opens unfiltered), paths, floating selections; text, vector and link layers open as their pixels.
- **Never panics:** every read is bounds-checked; canvases ≤ 300,000 px a side and 1 GiB of pixels, ≤ 8,192 layers, ≤ 1,024 channels, nesting ≤ 64, payloads ≤ 64 MiB, gzip inflation ≤ 1 GiB; tile data decoded to the exact declared size; the property lengths the spec warns about (`PROP_COLORMAP`, `PROP_USER_UNIT`) are computed, not trusted; cancellation checked per layer and per 64 tiles.
- **Wiring:** `IoError::Xcf`, detection by the `gimp xcf ` signature or the extension, `xcf` in File › Open, the batch commands and the web app; `docs/xcf.md`, the file-format parity table, the README Formats paragraph, `ATTRIBUTION.md`.

### How the composite differs from GIMP (documented in `docs/xcf.md`, each noted on open)

Three GIMP defaults have no Photoshop counterpart; the tests measure each:
- GIMP blends most modes and composites every layer in **linear light**; PhotoCraft (like Photoshop) in the document's encoding. A layer set to *RGB (perceptual)* in GIMP matches within 2.5/255 (the tolerance the tests enforce).
- Every mode but Normal composites with **Clip to backdrop**: the layer shows nothing where the layers beneath are transparent.
- For modes whose result can leave 0..1 (Addition, Subtract, Divide, Dodge, Burn, Linear light) GIMP **clamps after** applying the pixel's alpha; Photoshop before. Opaque pixels match exactly.

## How it was tested

- **Unit tests** (`crates/io/src/xcf/tests.rs`, 15): a small XCF writer built from the specification produces files for every compression (none, RLE, zlib), 16-bit and 16/32/64-bit float samples (big-endian), version 0 and 3 (32-bit pointers, legacy modes), properties (offsets, opacity, mode, visibility, locks, tags), groups by item path with pass-through and a path that leads nowhere, masks applied or not at the layer offset, indexed colour maps, extra channels and the selection, resolution/guides/comment/ICC parasites and unknown properties, clipping/text/vector/floating-selection reporting, RLE long runs and literals, limits and malformed structures, gzipped files, and every truncation of a file (never a panic).
- **GIMP-written fixtures** (`crates/io/tests/xcf.rs`, 13 tests; `cargo test -p photocraft-io --test xcf`): nine files written by GIMP 3.2.6 itself (`scripts/xcf_fixtures.py`, run inside GIMP) from procedural images the tests regenerate, plus `-perceptual` variants of five of them with every layer set to blend and composite in gamma-encoded RGB, each with GIMP's merged rendering as a PNG (28 files, 251 KB). Layer data is checked sample for sample (8-bit RGB/RGBA, 16-bit gray and gray+alpha, 32-bit float with values above 1, masks, offsets including off-canvas, opacity, modes, visibility, locks, tags, resolution, guides, groups and nesting, channels and the selection, indexed colour, a text layer). Our composite against GIMP's:
  - `layers-8bit-perceptual`, `mask-perceptual`, `text-perceptual`: within **2.5/255** everywhere; `gray16`, `indexed`, `channel`: within 2/255.
  - `groups-perceptual`: within 2.5/255 except the 15% of pixels where GIMP's Clip to backdrop hides the Multiply/Screen children above the transparent part of the background.
  - `legacy-modes-perceptual`, per mode: Addition, Subtract, Divide, Dodge, Burn, Hard light, Exclusion and Linear light within **2.5/255 on opaque pixels**; the translucent pixels of the unbounded ones differ by GIMP's clamp-after-alpha (measured 28–125/255, explained in `docs/xcf.md`); Grain merge, HSV Hue/Value and LCH Color are the approximations and are reported.
  - GIMP's default (linear-light) files: the known gap, measured and pinned: 38/255 (Multiply at 60%), 59/255 (mask edge), 73/255 (text edge), 138/255 (groups over transparency).
- `cargo test -p photocraft-io --lib --tests`: every binary ok. `cargo clippy -p photocraft-io --all-targets -- -D warnings`: clean (with the `as_chunks` form CI's clippy 1.99 asks for). `cargo fmt --all -- --check`: clean. `cargo check --target wasm32-unknown-unknown -p photocraft-io`: ok. `cargo xtask test-corpus -p io`: running when this PR was opened; its result follows as a comment.
- **Code review** (medium): 4 findings; 1 fixed (the linear-light note now covers every gamma precision, not only 8-bit), 3 left as follow-ups: GIMP's XMP/EXIF parasites are not imported yet, each drawable goes through a full-size f32 scratch buffer (bounded by the 1 GiB budget), and a damaged `PROP_USER_UNIT` fails the file instead of being skipped.
- Not done: GIMP's own `app/tests/files/gimp-2-6-file.xcf` (GPL) is not used; a local opt-in corpus of real-world XCFs would be the next step, as for PDN and Krita.
