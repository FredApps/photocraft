## Pinned upstream reproduction and regression specification

Fixes #6267.

**Cause.** `crates/io/src/smart_map.rs` had no mapping for these three Photoshop smart filters, so they imported as `psd.unsupportedFilter`. The stored composite showed them, but any re-render of the smart object (Replace Contents, Relink) dropped them.

**Fix.** New `KNOWN` entries and param mappings, both directions:
- **Sharpen** (`Shrp`): Photoshop stores no `Fltr`, only the name and `filterID`, so it is matched by `filterID` and written back with `hasoptions` false.
- **Dust & Scratches** (`DstS`): `Rds ` / `Thsh` ↔ `radius` / `threshold`.
- **Hue/Saturation** (`HStr`): `Clrz` plus `Adjs` `Hst2` entries (`H   `/`Strt`/`Lght`, and `LclR` with `BgnR`/`BgnS`/`EndS`/`EndR` for the six colour ranges) ↔ the `image.adjustments.hueSaturation` params. A range without bounds is written with Photoshop's defaults. `Hue ` is accepted on import too.

**Tests.** The known-filters round-trip test covers all three. A new test imports Photoshop's settings-less Sharpen item and checks that malformed Hue/Saturation and Dust & Scratches data fail cleanly. `cargo test -p photocraft-io --lib smart_map` passes and clippy is clean.
