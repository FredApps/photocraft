Follow-up to #5334, addressing @tanish2k09's review note there: `transformed_text_lands_where_resvg_draws_it` returned early, and passed without checking anything, when the import found no font.

## Why naming a bundled font isn't enough

- `photocraft_text::CRAFT_FONTS` is empty unless the build sets `CRAFT_FONTS_DIR` (`crates/text/build.rs`).
- SVG import doesn't load the bundled UI fonts (`fonts::BUNDLED`).

So with the system fonts hidden, an SVG naming `"Inter, …"` still imports no text. The merged test then passed in 0.00 s.

## Changes (test-only)

- The test moves into the `src/svg.rs` unit tests, so it can call `parse_with` (the same hook the existing `no_fonts()` test uses) with a font database holding only the bundled Inter Regular, which is always compiled in.
  - The resvg reference is rendered from the same parse, so both sides use the same face.
- The early return is gone: an empty import now fails, and the test expects exactly one text layer.
- The old copy in `tests/svg.rs` is removed.
- `text_becomes_outline_shapes_or_warns_without_a_font` stays either/or on purpose, because it exercises the real font lookup, where "no font, so a warning" is the correct behaviour.

## Tested

To hide the system fonts I used a private mount namespace with tmpfs over `/usr/share/fonts` and `/usr/local/share/fonts` (`fc-list` reported 0 fonts).

- **With the #5334 fix reverted:** the test fails, both with system fonts present and with them hidden.
- **With the fix:** it passes, including with system fonts hidden.
- **Unmodified `main`, fonts hidden:** the old test "passes" in 0.00 s.
- **All passed:**
  - `cargo fmt --all -- --check`;
  - `cargo clippy --workspace --all-targets --locked --features heif -- -D warnings`;
  - `cargo test -p photocraft-io`: 604 passed, 0 failed, 5 ignored (the existing ones that need external files);
  - `cargo xtask layers`.

**Not run:**
- `cargo xtask wasm`: only `#[cfg(test)]` code changed.
- The corpus tests: the downloads were blocked in my environment.
- The FreeBSD job: I couldn't check which fonts that VM has, because its setup lives in the shared `craft-common-actions` workflow. On Linux and Windows CI the old test most likely did run, since those images ship DejaVu or Arial. The point of this change is that the test no longer depends on the machine's fonts.
