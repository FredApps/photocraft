Fixes #7699.

`Compress-Archive -Path <folder>` archives the folder itself, so the portable zip contained

```
photocraft-<version>-windows-<arch>-portable\photocraft.exe
photocraft-<version>-windows-<arch>-portable\photocraft-cli.exe
photocraft-<version>-windows-<arch>-portable\portable.txt
...
```

rather than those files at its root. `<folder>\*` archives the contents.

Four things say the root is what was meant:

- this script's own synopsis — `photocraft-<version>-windows-<arch>-portable.zip   photocraft.exe + photocraft-cli.exe + portable.txt`;
- `portable.txt` ("While this file sits next to photocraft.exe…") and the advice to "copy the whole folder", which with a wrapper means the user's folder contains one more folder before the exe;
- VectorCraft's `packaging/windows/windows7.ps1`, which writes its portable zip with `Compress-Archive -Path (Join-Path $Stage '*')`;
- storytold/craft-launcher#627 — the launcher's portable install looked for the program at the archive root and found a wrapper folder instead. (That side now unwraps a single wrapper folder, so this is belt and braces; if you would rather keep the wrapper here, the launcher copes either way and the synopsis is what should change.)

Nothing read the layout back after writing it, which is how it drifted, so the three files are now checked inside the archive and the build fails loudly if they are not at its root.

### How this was checked

I have no Windows or PowerShell here, so I have not run `package.ps1`: the change copies the line that already works in `windows7.ps1`, and the check uses `Expand-Archive` + `Test-Path` + `throw` exactly as `sign.ps1` and this script use them. `packaging-lint` runs on this PR and is the static check; a maintainer running the packager on a Windows runner is the real one. No Rust is touched, so `cargo xtask ci` has nothing to say about it.
