Follow-up to #5234, as offered in its review.

Since #5234, a discrete card's own memory caps the GPU budgets, so a huge canvas can fall back to the reduced CPU canvas on a card with little memory. Nothing said why. System Info now shows the card's memory.

## Change

- `GpuInfo::lines()` adds **Graphics memory: {size}** after the driver line when the card reports its memory (`video_memory_mb`, from DXGI on Windows and amdgpu on Linux). It appears in both Help › System Info and Preferences › Performance › Graphics.
- The size uses the same compact format as #5973's "GPU memory budget" line (`chrome_ui::fmt_bytes`, e.g. `8.0G`), so the two lines compare directly.
- Integrated GPUs and cards that report nothing show no line: their textures share system memory, which the RAM-based budgets already cover.
- **Translations:** the new string is in all 20 catalogues, worded to match each catalogue's existing "GPU memory" term.

## Test

`system_info_shows_the_cards_memory`: with 8192 MB reported, the line `Graphics memory: 8.0G` follows `Driver: …`; with none, no such line appears and nothing else changes.
