Fixes #7862



### Problem

With the Slice Select tool and a slice selected, pressing Delete didn't delete the slice. The key went on to Layer › Delete, so in a one-layer document the status bar said "a document must keep at least one layer", and in any other document it deleted the active layer. Photoshop deletes the selected slice. The Delete button in the Slice Select options bar already did, but not the key.



### Solution

- **`crates/ui-egui/src/slice_ui.rs`, new `keys`:** Delete or Backspace with no modifiers deletes the selected slice through `slice.delete`, as the options-bar button does, and clears the selection. It acts only with the Slice Select tool and a selected slice, and not while a text field or a widget that deletes with these keys has focus.

  - **Locked slices** (View › Lock Slices) are refused with the message the options bar shows, and stay.

  - **An auto slice** has nothing to delete: it is made from the user slices around it. The key does nothing there, and still doesn't reach the layer.

- **`crates/ui-egui/src/shortcuts.rs`:** it runs next to the selected-guide handler (`guide_select::keys`), before the shortcuts that delete layers or clear pixels.



### Tests

`slice_ui::tests::delete_deletes_the_selected_slice_not_the_layer`, through the app's shortcut handling, for both Delete and Backspace:

- a slice drawn with the Slice tool and selected with Slice Select is deleted, the document keeps its layer, and no error is shown;

- with View › Lock Slices on, the slice stays and the status says the slices are locked;

- with an auto slice selected, nothing is deleted and the layer stays.



It fails without the change: the key never reaches the slice handling.
