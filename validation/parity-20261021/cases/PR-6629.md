Follows up #6592, which #6625 closed by keeping the transform box and the Pen path on screen during a pan. This PR does the same for every other canvas overlay (paths, guides, grid, crop, slice, gradient, artboard) and replaces #6625's special case with the general fix.

## Problem
The Pen path, finished or still being drawn, disappeared while you panned the canvas with Space. In fact *every* canvas overlay (paths, guides, grid, the transform box, crop/slice/gradient/artboard overlays) was skipped for as long as a Hand drag lasted: the Hand tool, Space or the middle mouse button. In `canvas_view` they were drawn under `if primary && !(hand_pan && response.dragged())`. This dates back to when the overlays sat in the `else` of the pan branch; #3610 had patched only the transform box.

## Fix
- Overlays always draw, so they move with the image during a pan, as in Photoshop.
- Only the tool-cursor chain is skipped while panning, so the fist cursor (#2196) is kept.
- The transform-only special case from #3610 is removed; the general fix covers it.

## Tests
- New `hold_keys::tests::the_pen_path_being_drawn_stays_visible_while_space_pans`: draws two anchors, holds Space and drags. Mid-pan it checks the segment is painted at its new screen position and the fist cursor shows. After release, the path is still in progress. Fails without the fix.
- `transform_preview_stays_visible_while_panning` (#3610) still passes.
