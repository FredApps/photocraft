### Cause

The `.atn` event table (`crates/engine/src/atn_cmds.rs` `EVENTS`) had no entries for `autoCutout`, `smartBrushWorkspace`, `colorRange` or `groupEvent`, and the converters for events it did know missed shapes common in retouching sets:

- `selectiveColor` was mapped, but the `Clrs` table used `Yllw` (the yellow-ink key) for the yellows range. Photoshop writes `Ylws`, so any Selective Color step that touched yellows failed to convert. Export wrote the same wrong code.
- `make` did not handle Add Layer Mask (a `Chnl` made at the mask channel).
- `set` did not handle setting the foreground or background colour.

### Fix

| `.atn` event | command | params translated |
|---|---|---|
| `autoCutout` (Select Subject) | `select.subject` | `sampleAllLayers` |
| `smartBrushWorkspace` (Select and Mask) | `select.refineEdge` | radius, smart radius, smooth, feather, contrast, shift edge, decontaminate + amount, output, sampleAllLayers |
| `selectiveColor` / `SlcC` | `image.adjustments.selectiveColor` (and the adjustment layer) | the yellows range is read as `Ylws` and now exported as `Ylws`. Legacy `Yllw` from older PhotoCraft exports still reads |
| `colorRange` / `ClrR` (presets) | `select.colorRange` | reds…magentas, highlights/midtones/shadows (fuzziness and range limits), skin tones (fuzziness), out of gamut, invert |
| `groupEvent` / `GrpL` | `layer.createClippingMask` | target or named layer |
| `ungroup` / `Ungr` | `layer.releaseClippingMask` | target or named layer |
| `make` of a layer mask (`UsrM` `RvlA`/`HdAl`/`RvlS`/`HdSl`) | `layer.layerMask.revealAll` / `hideAll` / `revealSelection` / `hideSelection` | none |
| `set` of `FrgC` / `BckC` (RGB, HSB or gray) | `tools.setColors` | `foreground` / `background` |

All of these also export back to the same Photoshop events, except Select and Mask, which still exports as `refineSelectionEdge` like before.

Steps whose parameters can't be translated faithfully still import as kept Photoshop steps and are reported as unsupported. That covers Color Range with Sampled Colors (a Lab min/max range), Color Range with any key the converter doesn't know, mask/colour variants other than the ones above, and colours in Lab, CMYK or a colour book.

**`groupEvent` is not Group Layers.** The issue suggests `layer.new.group`, but Photoshop's `groupEvent` (`GrpL`) is Create Clipping Mask (the old "Group with Previous"). Grouping layers is recorded as `make` of a `layerSection`, which was already mapped. This matches the high-pass sharpening action (duplicate, High Pass, blend mode, clip).

### Tests

- `retouching_set_events_map_to_their_commands`: synthetic Photoshop-shaped descriptors for each new mapping, written as stringID events like the issue's file (`autoCutout`, `smartBrushWorkspace`, `selectiveColor` with `Ylws`/`Whts`, `colorRange` skin tones, `make` mask, `set` foreground, `groupEvent`). Each one is checked against the expected (command id, params). Sampled Colors, an unknown Color Range key, a Lab colour and an unknown event still report unsupported. Legacy `Yllw` still reads.
- `every_mapped_command_exports_and_imports_back`: round-trip cases for `select.subject`, `select.colorRange` (4 shapes), both clipping-mask commands, the 4 mask commands, `tools.setColors` (fg and bg) and yellows in Selective Color.

### Not in this PR

- **`Adobe Camera Raw Filter`**: skipped. The descriptor layout of a recorded Camera Raw step isn't verified. `photocraft-io`'s Camera Raw decoder only accepts the PSD smart-filter layout (process version 5/6, known keys only). Mapping it without a real recording risks running with wrong values. A sample `.atn` from the reporter would settle it.
- **`move`**: skipped. Layer nudges in px/pt and Bring Forward/Send Backward/Front/Back already map. The remaining shape seen in recorded sets moves a layer to an absolute index (a panel drag). That index has no meaning in another document, so it stays unsupported.
- **Other `set` / `make` shapes** in the reporter's file can't be identified without it (blend mode, opacity, fill, name and visibility on a layer were already mapped). With the file, `actions.load`'s `unsupported` list names each step that is left.
- `docs/gaps.md` G11 is not updated here.
