Closes #7921.

Smart Blur read each neighbour one channel at a time through bounds-checked `Image::get`. On High quality that is 441 neighbours per pixel at radius 12, which took 6.25 s on 24 MP.

## Change (`crates/algo/src/blur2.rs`)

- Neighbour offsets are precomputed as sample offsets into the source window.
- Normal mode with 1–5 channels sends interior pixels (those whose whole kernel lies inside the window, which with the usual halo is every pixel) through `smart_rows::<N, A>`. Each offset sweeps a whole row, so loads are contiguous. A rejected neighbour adds `-0.0`, an exact identity, instead of branching.
- Every pixel still sums its neighbours in the same order as before, so **the output is bit-identical**.
- Border pixels, Edge Only / Overlay Edge, and layers with 6+ channels keep the per-pixel path, now with precomputed offsets.
- If the row pass ever stops early it returns only the rows it finished, so the per-pixel fallback never reads an already-blurred centre.

## Timings

`cargo run --release -p photocraft-algo --example bench_filters2 smart`, 6000×4000 RGBA8, High quality, 20 threads:

| radius | before | after | speedup |
| --- | --- | --- | --- |
| 3 | 0.55 s | 0.23 s | 2.4× |
| 12 | 6.25 s | 1.78 s | 3.5× |
| 100 | 3.64 s | 0.95 s | 3.8× |

`bench_filters2` gains the r12 and r100 rows (it only measured r3, which hid the slowdown). I also tried a planar (one array per channel) layout with per-channel passes. It was slower (r12 2.85 s), so it isn't included.

## Tests

`crates/algo/src/smart_blur_tests.rs` keeps the previous kernel as an oracle and compares bits across:

- Rgb, Gray, Cmyk and Lab layouts, plus Multichannel with 1–8 channels, each with and without alpha;
- radii 0.1–17.5, all three qualities, all three modes, two thresholds;
- output rects that are the usual tile, the whole window, overhanging the window, and empty;
- NaN, ±inf and -0 samples, and a 1 px window where every neighbour is outside.

Both fast paths were mutation-checked: breaking either one fails the oracle test.
