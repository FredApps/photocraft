## What's wrong

Double-clicking a Liquify smart filter in the Layers panel opens the generic parameter form, whose only field is Mesh Size, instead of the Liquify workspace. `smart_ui::open_editor` (`crates/ui-egui/src/smart_ui.rs:280-311` on `main`) sends Camera Raw and the Filter Gallery to their own dialogs, adjustments to their Image › Adjustments editors, and every other filter to `filter_dialog`. OK on that form replays the recorded strokes on the form's mesh size. Filter › Liquify always opens with no strokes (`liquify_ui.rs:466`), so the recorded strokes cannot be edited again.

To see it: make a smart object, run Filter › Liquify, drag one stroke, press OK, then double-click the Liquify row under Smart Filters.

## What changed

- `open_editor` sends a Liquify smart filter to a new `liquify_ui::open_smart_filter`.
- `open_smart_filter` opens the workspace on the smart object's pixels below that filter, with the filter's recorded strokes and mesh size, as `gallery_ui::open_smart_filter` does (#3426).
- OK then runs `layer.smartFilter.setParams` with the strokes and the mesh size in one history step, and no second Liquify filter is added. OK after Restore All leaves the filter with no strokes. Cancel leaves the filter unchanged. Filter › Liquify on a smart object still adds a new filter.

Ten-W reported this in #6571. Part of #6571: the Puppet Warp and Perspective Warp smart filters it also lists are left for later.

- `smart_filter_double_click_edits_the_recorded_liquify` checks the workspace's strokes, mesh size and source pixels, then that a new stroke and OK update the filter in one step and Undo restores it. Without the new `open_editor` branch it fails at "no generic parameter form".
