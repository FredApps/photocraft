Fixes #5247

A plain `cargo build` from `main` reported `photocraft --version` as `0.8.2 (dev build)`, which doesn't say which commit a bug report is about. It now reports `0.8.2 (dev build, 6f8505421)`.

**How:**
- `apps/photocraft/git_checkout.rs` is a build-script helper shared by the desktop and CLI `build.rs`. It runs `git rev-parse HEAD` and emits `PHOTOCRAFT_CHECKOUT_SHA`, and it asks for a rerun when `HEAD` or the current branch's ref changes (so on a commit or checkout). This works in worktrees as well.
- At startup the binaries pass that value to the new `build_info::set_checkout`. `long_version()` uses it only when `PHOTOCRAFT_BUILD_SHA` is unset.
- The engine still doesn't shell out to git (the existing design note in `build_info.rs`). The value lives in the two app crates, so a new commit rebuilds only those and not the engine and everything above it. I checked: after an empty commit, only `photocraft-cli` recompiled (17 s), and `--version` showed the new hash.

**Release logic unchanged:** when `PHOTOCRAFT_BUILD_SHA` is set (CI, `packaging/`, Docker), the build script does nothing and the output stays `0.8.2 (<sha>, <date>)`.

**Fallbacks:** with no git, no checkout, or a workspace that isn't the root of the repository it sits in (for example a source tarball unpacked inside another repo), nothing is set and the output stays `(dev build)`.

`docs/releasing.md` now mentions the dev-build format. Unit tests are in `build_info::tests::long_version_formats`.
