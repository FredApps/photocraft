Fixes #4968.

`atomic_write` and the directory-bundle writer renamed the new file into place, then discarded the result of flushing the directory (`let _ = fs.sync_dir(&dir)`). Until that flush succeeds, the rename may not survive a power loss or crash. Yet the save reported complete success. Callers act on that success, so the risk was real:
- the document is marked saved;
- its crash-recovery entry is discarded;
- a bundle save goes on to remove the objects only the old manifest referenced.

The directory flush is real on Unix only (it's a no-op on Windows), so this affects Linux and macOS.

## Change

- **Flush failures are reported.** When the flush fails, `atomic_write` now returns an error. It keeps the error's kind and says the file was written but the save may not survive a power loss or crash. The caller then treats it as a failed save: the document stays unsaved, its recovery data stays, and the user can save again or elsewhere.
- **Bundle saves stop early.** The bundle writer (`write_bundle_file`) does the same. A failed flush after writing the manifest now stops the save before it removes unreferenced objects.
- **Unsupported flushes still count as saved.** A file system that can't flush directories at all still saves normally (`dir_synced`). That means EINVAL (some Linux file systems), ENOTSUP or EOPNOTSUPP, ENOTTY on Apple platforms, or `ErrorKind::Unsupported`. Retrying won't change those, and failing every save there would make saving impossible.

A folder that can't be opened for the flush at all, because it has write and search permission but no read permission, also counts as saved (`open_dir_for_sync`). No flush can be attempted there, and the existing permission tests save into such folders.

The errno values are spelled out per OS, as the existing Apple full-flush fallback already does, so no Unix-only API is needed.

## Tests

- `a_failed_directory_flush_is_reported_not_swallowed` injects a failing `sync_dir` through `AtomicFs`. The save returns an error of the same kind whose message names the file and says it may not survive. The new bytes are in place and no temporary file is left.
- `a_directory_flush_the_file_system_cannot_do_still_saves`:
  - an `Unsupported` flush still saves;
  - EINVAL counts as unsupported on Unix only;
  - EIO is an error.

The bundle writer's flush runs on Unix only, and this machine is Windows, so it has no test of its own here. It reuses `dir_synced` and returns before cleanup, which the format tests cover on every platform.
