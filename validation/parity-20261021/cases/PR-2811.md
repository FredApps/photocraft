The Cryptomatte picker on top of the merged #2180 codec — the Arnold/V-Ray/Redshift workflow: click an object in the render, get its exact selection.

**`select.cryptomatte {x, y, layer?, tolerance?, mode?}`**

- Reads the ID at the clicked pixel of the active document's **source EXR** (the Cryptomatte layer by name, default the first; the document must have been opened from a saved `.exr`, everything else says so).
- Builds the selection from every pixel that ID **covers** — partial coverage becomes a partial mask, so an edge falls between both objects instead of hard-cutting. `tolerance` groups near-identical IDs (default 0: exact).
- Returns the ID, the **manifest's object name**, the pixel count and the layer used — the name is what a status-bar line or MCP caller shows.
- `mode` replace/add/subtract/intersect combines like the marquee tools; clicking a pixel with no samples deselects in replace mode (Magic Wand behaviour).

Everything is a command, so the control channel, CLI and MCP drive the same selection headlessly; the UI picker panel can follow as a thin shell.

**Tests** (synthetic 4×4 file: `cube` at coverage 1 on the left half, `sphere` at 0.5 on the right, manifest naming both): exact pixels and name for a full-coverage click, 0.5 mask at the half-covered pixel, add/subtract arithmetic (0.5 − 0.5 → 0.25), layer-by-name, and a hostile-param sweep (missing, non-numeric and out-of-bounds coordinates, unknown layer and mode — all `Err`, never a panic). `panic_hunt` green; engine suite 1161 green; clippy/fmt clean.
