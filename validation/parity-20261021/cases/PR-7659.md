## Pinned upstream reproduction and regression specification

Closes #7278.

Rotating or scaling a type layer whose font is missing set the text again in a substitute font. Free Transform updates the layer's transform, then `refresh_text` re-renders the text with whatever face the font database supplies. With the font missing, that is the fallback, so the glyphs change on commit even though the preview showed the original pixels turning.

### Photoshop, checked

I used a PSD with "Missing" set in Chalkduster, with the font name in the file changed to `Chalkdustqz` so neither app can find it.

- **⌘T:** Photoshop 2025 says the fonts are missing and the layer "may look fuzzy or pixelated if you transform it". It offers Transform or Cancel.
- **On Transform:** a 15° rotate turns the existing Chalkduster pixels. The layer stays a type layer, and its font still reads `[Chalkdustqz]`.

### Change

- **`transform_cmds::apply_transform`:** for a type layer with missing fonts and a rendered cache (`keeps_pixels`), the cache is warped with the transform, the way a smart object's fallback cache is. The layer's `transform` still updates as before.
- **`refresh_text`:** for such a layer, it only rebuilds the TySh record through the new `type_cmds::refresh_record`, so a PSD save carries the new transform. It doesn't re-render the text.
- **`check_layer_budget`:** now prices that warp too, so an oversized one is refused before anything changes.
- **Unchanged:** a type layer whose fonts are all present still re-renders from its transform, so it stays sharp. Distort and Perspective on type are still refused.

Not in this PR: Photoshop's confirmation dialog before the transform. This PR keeps PhotoCraft's existing missing-font warnings and just transforms.

### Tests

- New: `a_type_layer_with_a_missing_font_transforms_its_pixels` (transform_cmds). It creates a type layer in a missing font and gives it pixels the fallback face would never draw, as a PSD would. After a translate, it checks that:
  - the layer is still a type layer with the new transform;
  - the same pixels moved by the translation;
  - the TySh record is rebuilt.

  It fails without the fix, because the cache is re-rendered with the fallback face.

### Verified in the app

On macOS 27 with a release build, side by side with Photoshop 2025, using the same PSD:
