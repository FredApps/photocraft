Fixes #7670.







Ripple accepts fractional amounts: `{"amount":81.4,"size":"small"}` produces the same pixels in direct execution and native action playback. Strict ATN export previously rounded `Amnt` to 81 and succeeded without skipped steps. Reimported playback changed the image without warnings.







Refuse fractional Ripple amounts through the existing unsupported-step path. Add an exact integer field converter, used only for Ripple's `Amnt`, which checks that conversion to the existing integer descriptor neither rounds nor saturates. Strict Save Actions now reports the unsupported step; opt-in `skipUnsupported` omits it and reports its action, index and command ID. Whole amounts, sizes and omitted defaults retain their existing binary representation and playback. Native Ripple execution, import, the shared rounding converter and the plain-event target guard keep their existing behavior.







Regression coverage:







- Exercise six positive/negative fractional amounts across all three sizes and 8/16/32-bit documents (54 cases). Verify native playback agrees with direct execution and strict export refuses the fraction. The 81.4 vs 81 pixel control proves the fixture exposes the reported loss at every size and depth.



- Compare direct, native and binary ATN playback for integer bounds, signed/zero controls and omitted/null parameter defaults (54 cases); inspect integer `Amnt` in serialized descriptors.



- Verify exact skipped-step reporting and the order/values of retained integer steps in a mixed action.



- Retain refusal of non-pixel targets and malformed fields.
