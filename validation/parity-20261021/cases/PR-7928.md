Fixes #7910



### Problem

With the Rectangular or Elliptical Marquee set to Style › Fixed Size, Width and Height were pixel fields only. To select, say, 50 × 30 mm, you had to work out the pixels at the document's resolution yourself. In Photoshop, a right-click on these fields picks their unit (px, in, cm, mm, pt, pica, %).



### Solution

`crates/ui-egui/src/panels.rs` (marquee options bar):

- **Unit menu:** with Fixed Size, a right-click on Width or Height opens the length-units menu that the rulers and Free Transform's W and H already use (`rulers::unit_menu`), with the current unit checked.

- **Display:** both fields show the size in the picked unit, converted at the active document's resolution (72 ppi without a document). Percent is of the document's width or height.

- **Typing:** a number typed is in that unit; a typed unit ("2 in") converts as before.

- **Exact pixels:** leaving a field re-reads the rounded text it showed; when that is all that happened, the pixels are kept, so a unit that rounds doesn't nudge the size.

- **Storage:** the size is still kept in pixels (`marquee_width`/`marquee_height`), so the marquee drag and saved tool options are unchanged.



`crates/ui-egui/src/state.rs`: the picked unit is a new tool option, `marquee_unit` (default `pixels`, `serde(default)` so older settings load), and Reset Tool resets it (`tool_reset.rs`).



Fixed Ratio's fields stay plain numbers.



### Tests

`fixed_size_shows_and_takes_the_unit_picked_on_its_fields`, driving the options bar in a kittest harness (a 254 ppi document, so 10 px = 1 mm):

- Fixed Size 100 × 50 px shows 100 and 50;

- right-click on Width › Millimeters shows 10 and 5, and the stored size is still 100 × 50 px;

- typing 20 into Width then gives 200 px;

- in Inches, entering and leaving Height (50 px, shown as 0.197 in) without an edit keeps 50 px, not the 50.038 px the rounded text reads back as.



It fails without the change: the right-click opens no unit menu.
