Part of #6528 (solo/restore).

### Cause

When the layers exceed the GPU memory budget, a large visibility change is redrawn by the CPU compositor in 1024 px blocks (`background_redraw`). Each finished block was uploaded to the canvas texture and dropped, and nothing remembered which document state a finished redraw showed. Alt-clicking an eye to solo a layer (which fits the GPU) overwrites the texture, so the restore composites every layer again from scratch (about 4 s on a 50 MP PSB, ~100 s on a multi-GB PSB), and a second restore is no faster.

### Fix

`background_redraw` now keeps the texels of its last two finished redraws (`KeptComposites`), keyed by the whole `Arc<Document>` they drew, plus the display transform's texture key, the texture format and the block grid. A redraw that starts for a state equal to a kept one uploads those blocks instead of compositing (perf kind `kept`).

- **Exact key.** The key is the document itself, compared with `==` (same approach as the GPU compositor's prefix cache in `crates/gpu/src/prefix.rs`): layer pixels (Arc-shared tiles compare without reading pixels), visibility, opacity, blend, masks, adjustments and every other document field. It can miss more than strictly needed (e.g. a selection changed in between), never hit stale. A redraw that is restarted on an edited document drops the blocks it collected from the old state, so only a composite drawn entirely from one state is kept.
- **Bounded memory.** At most two composites, within what Memory Usage leaves beside the document's own pixels and History (`history_budget_bytes() - memory_bytes()`); a collection that would pass that cap is abandoned, the cap is re-checked (and older entries dropped) at every fresh redraw, and a closed document's entries go with it.

### Tests

- `kept_composites_come_back_only_for_the_exact_state_and_stay_bounded`: store; hit on the same state (also an equal document in another `Arc`, as after a solo + restore); miss on a visibility, opacity, blend or pixel change, another display key, texture format or block grid; LRU eviction at two entries; byte cap; closed documents.
- `showing_a_hidden_layer_again_reuses_the_redraw_from_before_it_was_hidden` (GPU, skips without an adapter): hide then show a layer on a CPU-only document; the show starts no redraw, reports `kept`, and the texture matches the synchronous CPU composite; a later opacity change composites again.

Locally the unit test passes. The GPU harness on this machine crashes with an access violation inside the driver, also on the existing `a_full_cpu_refresh_draws_in_the_background_with_the_synchronous_pixels`, so the GPU test relies on CI here. Clippy wasn't run locally.

### Not in this PR

- The second part of #6528, "raising Memory Usage doesn't change the GPU budget" (the budget stays 3006 MB at 50000 MB): untouched.
- Only states drawn by the background CPU redraw are kept. A state first drawn on the GPU (or by a synchronous CPU refresh) isn't, so e.g. a solo that is itself over budget still composites once before its own restore can hit; a stack-prefix cache (re-blend only the layers above the toggled one) would be the next step.
