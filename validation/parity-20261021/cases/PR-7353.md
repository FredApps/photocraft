## Pinned upstream reproduction and regression specification

The following is source material from the approved PR, not a record of testing this combined build. Test the stated scenario, values and regression names in addition to the procedure above.

Follow-up to #5469, addressing @FredApps' non-blocking testing nit from the merged review: "fail_next_for_test currently fails the **first** buffer allocation, so this command regression does not independently exercise failure of the second mask allocation. A fail-after-one allocation test would protect that path too." The same re-review noted "The assertions do not directly compare document pixels"; the new test does. No runtime code change: every added line is `#[cfg(test)]` or inside test files, so non-test builds compile byte-identically to current `main`.

## What

1. `crates/engine/src/allocation.rs` — a second test-only thread-local flag with the helper `fail_after_for_test(skip)`: the failpoint trips only on the allocation/checkpoint after `skip` clean attempts, so a test can make a *later* fallible call fail, not just the first. `fail_next_for_test` keeps its exact one-shot semantics (`skip = 0` is equivalent); `capacity` and `checkpoint` now consult one shared `cfg(test)` helper (`failpoint_hits`) instead of each consuming the boolean. New unit test `fail_after_trips_only_on_the_counted_attempt` pins the counting: two clean attempts, the third fails with the same `not enough memory` error, the flag is then consumed.

2. `crates/engine/src/brush_cmds/tests.rs` — new regression `define_brush_from_selection_survives_failure_of_the_second_allocation`: `fail_after_for_test(1)` counts the tip buffer (`allocation::filled`) as the one clean attempt and fails the selection-mask read (`allocation::read_region`) instead. The test asserts the graceful error text ("not enough memory for defining a brush from the selection"), and that the current brush, the preset list, the history length and — now directly compared — the document pixels themselves are unchanged. The existing one-shot regression `define_brush_from_selection_survives_allocation_failure` (unchanged) keeps covering the first buffer.
