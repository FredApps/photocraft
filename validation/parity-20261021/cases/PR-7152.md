## What's wrong

`crates/text/build.rs` embeds every font in craft-fonts' `fonts/manifest.txt`, but `FontDb::new` registers only the entries whose scripts include `Jpan` (`crates/text/src/fonts.rs:227` on `main`). craft-fonts `8dcdacd5` adds Noto Sans CJK SC and Noto Sans Arabic, and `3d9ab3a1` (its `main`) adds Noto Sans Thai. Built with either, the binary carries those fonts, but the font list does not show them and text layers do not fall back to them, although the fallback lists name all three (`fonts.rs:63`, `:67-68`, `cjk.rs:211`). In `TextEngine::new()`, 中文图层 set in Inter lays out with 2 `.notdef` glyphs of 4, and مرحبا lays out with 5 `.notdef` glyphs of 5. `tests::works_without_craft_fonts` fails ("Noto Sans CJK SC registered under its manifest name"). CI checks out craft-fonts at `abb83316`, which has only Japanese fonts.

## What changed

- `FontDb::new` registers every `CRAFT_FONTS` entry through a new `register_craft_fonts`. A single-face file registers under its manifest family, whatever family its `name` table gives (`FontInfoOverride`, as `select_named_face` uses it). Each face of a collection keeps its own family.
- Behavior change: with Noto Sans CJK SC built in and no Simplified Chinese system font, Japanese text set in Inter takes Noto Sans CJK SC when the UI locale is not Japanese, in the order `cjk::script_order` gives shared Han. `craft_fonts_cover_japanese_without_system_fonts` now expects the first CJK craft family in that order.
- Comments that said craft-fonts holds only Japanese fonts are updated.

#2169 by diax7 registers the Arabic craft fonts and makes `build.rs` embed only Japanese and Arabic lines; this change keeps `build.rs` and registers every embedded font.

## Tests

- New `craft_fonts_of_every_script_register_under_their_manifest_families` registers in-memory `Hans`, `Arab` and `Jpan` entries made from Inter and checks their families and the fallback stack; it fails with the `Jpan` filter back, with or without craft-fonts.
- New `craft_font_collections_keep_their_face_families`: a two-face collection keeps its faces' families. It fails when collections take the manifest family.
- New `craft_fonts_cover_their_other_scripts_without_system_fonts`: 中文图层, مرحبا and ภาษาไทย set in Inter lay out without `.notdef` when the build has a craft font for the script. With the `Jpan` filter back it fails.
- `tests::works_without_craft_fonts` fails on `main` at `efa1edd` with craft-fonts `8dcdacd5` and `3d9ab3a1`, and passes with the change.
