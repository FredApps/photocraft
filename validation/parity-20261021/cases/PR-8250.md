## Problem

A PSD smart object with a `warpCustom` warp whose `warp.bounds` sit off the contents' own `0..Sz` rect (the reporter's file: bounds -425, -675 to 2425, 2175 over a 2850 × 2850 source) re-rendered shifted. Edit Contents or Replace Contents moved the contents 15 % / 24 % into the frame and cut off their right and bottom edges. `Warp::map` evaluates the mesh at `(x - bounds.left) / w`, and the import took `bounds` from the file as is. Photoshop draws the mesh over the source rect; `bounds` only frames the control points.

## Solution

- **Import** (`blocks::parse_placed_warp`): a `SoLd` / `SoLE` custom warp spans the source rect `0..Sz` (`over_source`). This runs after the existing "moves nothing" check, so identity meshes over offset bounds still read as no warp, as before. Preset styles keep their box, since they are built from it.
- **Export** (`smart_map::sold_bytes`): a custom warp made in PhotoCraft can still be stored over another box (the warp box's image in source space, or the hull frame from #4113). It is re-expressed over the source rect with the new `Warp::over_box`, so it reopens drawing the same. `over_box` is exact: each new patch is a piece of one old patch, or of its clamped edge where the box runs past the old one. `Trnf` is computed from the stored warp as before, so the placement round-trips.
- **Export keeps the file's warp:** an imported `warp` / `quiltWarp` block that still reads as the layer's warp is written back verbatim, with its own `bounds`.

`PlLd` records (CS2 and older) store no source size and are left as they were. In-app editing and `.pcraft` keep the warp's own box; only the PSD mapping changes.

## Tests

- `blocks::tests::offset_custom_warp_bounds_still_span_the_source`: the reporter's numbers (Sz 2850 × 2850, bounds -425, -675 to 2425, 2175, a bent mesh). The source corners land on the mesh's corner points.
- `smart_map::tests::custom_warp_bounds_off_the_source_round_trip`: a warp made here over a box past the source is written over the source rect, reads back drawing the same, and keeps its placement. An imported block with offset `bounds` reads the same and is written back unchanged.
- `geom::warp::tests::over_box_keeps_the_surface`: a box inside the old one, a box past it, a box across a patch boundary, and the same box. Also checks that presets and empty or non-finite boxes are unchanged.

All three fail without the fix.
