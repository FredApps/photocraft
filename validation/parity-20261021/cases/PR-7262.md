### Problem
In `crates/engine/src/atn_cmds.rs`, `layer_ref(p: &Value)` converted any layer reference that was not a string (`Value::String(n)`) into the target layer reference (`target_ref("Lyr ")`).
When an action step explicitly specified an unselected layer by its numeric ID (e.g. `layer: 42`), exporting to `.atn` silently fell back to targeting the currently selected layer(s). Running such an action in Photoshop would modify/delete the wrong layer(s) instead of failing or skipping.

### Fix
- Updated `layer_ref(p: &Value) -> Option<D>` to return `Some(target_ref("Lyr "))` only when `layer` is missing or null, `Some(name_ref("Lyr ", n))` when `layer` is a string, and `None` when given explicit numeric layer references (or any other unsupported non-string representation).
- Propagated `Option<D>` via `layer_ref(p)?` to all callers (`make_to`, `set_to`, `transform_to`, `delete_to`, `visibility_to`, `move_to`, `duplicate_to`).
- In strict export (`skipUnsupported: false`), commands with numeric layer references fail gracefully. With `skipUnsupported: true`, such steps are cleanly skipped and recorded in `skipped`.

### Verification
- Added regression test `numeric_layer_references_refuse_silent_fallback_to_current_selection` in `crates/engine/src/atn_cmds/tests.rs` covering named references, omitted/target references, explicit numeric references across multiple command types (`layer.delete`, `layer.duplicate`, `layer.translate`), and `skipUnsupported: true`.
- `cargo test -p photocraft-engine --lib atn_cmds` passed (12 of 12 tests green).
- `cargo fmt --all -- --check` is clean.
