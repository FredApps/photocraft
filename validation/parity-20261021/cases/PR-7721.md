Fixes #7669.

Crystallize with `{"cellSize":5.4}` produces the same pixels in direct execution and native action playback. Strict ATN export used to write integer `ClSz = 5`, succeed without skipped steps, and replay a different image after import without warnings.

Refuse fractional Crystallize cell sizes through the existing unsupported-step path. An exact integer field converter, used here only for Crystallize's `ClSz`, checks that conversion to the existing integer descriptor neither rounds nor saturates. Strict Save Actions reports the action and step; opt-in `skipUnsupported` omits the step and reports its action, index and command ID. Integer sizes, defaults, import and plain-event target restrictions retain their existing behavior. Native Crystallize and its pixel algorithm are unchanged.

This uses the same exact integer field kind proposed in #7708, but is a separate commit based on main: it includes no Ripple behavior change and does not depend on that PR's commit. It does not address the separate seed issue #7668. The existing global integer rounding converter is unchanged; #7588's out-of-i32 guard still rounds fractional values and does not cover this issue.

Regression coverage:

- Six fractional sizes across 8/16/32-bit documents (18 cases): native playback equals direct execution, strict export refuses the fraction. A synthetic 24×18 fixture proves 5.4 differs from 5 at every depth.
- 27 direct/native/binary-ATN playback triples for integer controls, 3/300 bounds, an integer-valued float, omitted and null parameter defaults. Inspect integer `ClSz` in serialized descriptors.
- Precise strict error and opt-in skipped-step reporting; retained integer steps keep their order and values.
- Non-pixel targets, malformed fields and integer overflow are refused.
