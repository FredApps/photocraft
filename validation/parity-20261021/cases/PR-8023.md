Found while testing `crates/cms/src/lutfile.rs:111 (parse_cube) and :227 (write_cube)` (no existing issue): .cube LUT title containing '#' is truncated when the file is read back.

## Cause
`parse_cube` strips comments with `line.split('#').next()` on every line, including the `TITLE "..."` line. A title such as `Look #3` is therefore cut at the `#`, and the closing quote is lost.

## Fix
On a `TITLE` line with a quoted string, comment stripping now starts after the closing quote, so a `#` inside the quotes is kept as part of the title. A trailing `# note` after the closing quote is still treated as a comment.

## Verified
- Regression test `lutfile::tests::cube_title_with_hash_round_trips`: fails on `main` without the fix and passes with it (`cargo test -p photocraft-cms --lib cube_title_with_hash_round_trips`).
- `cargo xtask ci` passes.

## Not changed
`write_cube` is unchanged because it already writes the title in double quotes. Comment handling on other lines, and on `TITLE` lines without a closing quote, is unchanged.
