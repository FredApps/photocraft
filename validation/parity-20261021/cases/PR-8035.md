Closes #8037.

`photocraft-cli mcp` and `serve` silently accepted launch options they then ignored. `mcp stray.psd` went straight into MCP initialization. A repeated option quietly kept its last value. `--control-token-file` without `--bridge`/`--port` did nothing. In bridge mode, `--automation-read-root`/`--automation-write-root` were dropped even though the desktop process holds the roots, so the flags suggested file access that was never granted.

## Change (`apps/photocraft-cli/src/lib.rs`)

- New `validate_server_args`, run after parsing and before any server starts. For `mcp` and `serve` it refuses:
  - positional arguments;
  - an option given twice (`--flag v` or `--flag=v`);
  - empty values;
  - `--control-token` together with `--control-token-file`;
  - explicit token flags without `--bridge` (mcp) or `--port` (serve);
  - root flags on `mcp --bridge`, with an error saying to set them on the desktop app.
- Every subcommand: a flag where a value should be (`--format --quality 80`) is now "needs a value" instead of becoming the value. `--help`/`-h` in that position still prints usage. `--flag=--value` still passes a value that starts with `--`.
- These are usage errors: exit 2, message on stderr, stdout left empty for the protocol.
- Token environment variables (`PHOTOCRAFT_CONTROL_TOKEN`, `PHOTOCRAFT_CONTROL_TOKEN_FILE`) are still ignored in headless/stdio mode on purpose, so one left in a shell profile doesn't break headless use.

No documented launch line changes meaning. I checked every `mcp`/`serve` example in `docs/`, `book/` and the README.

## Docs

- `photocraft-cli --help`, `docs/mcp.md`, `book/src/automation/cli.md` and `book/src/automation/mcp.md` describe the rules and recommend absolute root paths in MCP client configs.

## Tests (`apps/photocraft-cli/tests/cli.rs`)

- `server_modes_reject_ignored_or_conflicting_options`: each refusal above for both `mcp` and `serve`, checking exit 2, the message and an empty stdout.
- `server_validation_does_not_consume_stdio_or_create_files`: four launch lines (stray positional, repeated root, repeated `--port`, repeated `--control-token-file`). Before this change each would have started a TCP server and written the token file. With stdin held open, each now exits 2 and creates no token file.
- `every_subcommand_answers_help` and `unknown_flags_are_usage_errors`: help in a value position, a missing value in `batch`, and the `--flag=--value` form.
