Fixes #6827.

**Cause:** `prefs::normalize_shortcut` Title-cased multi-letter key names, so a shortcut recorded in Edit › Keyboard Shortcuts as `Shift+PageUp` was stored as `Shift+Pageup`. egui's `Key::from_name` is case-sensitive, so `shortcuts::parse` returned `None` and the binding was silently dropped. This is why Flip Horizontal/Vertical on Shift/Ctrl/Alt+Page Up/Down did nothing, while the same commands on other keys worked. Arrow keys (`Arrowleft`) and other camel-case names were affected the same way.

**Fix:**
- `crates/engine/src/prefs.rs`: `normalize_shortcut` keeps egui's spelling for camel-case key names (PageUp, PageDown, Arrow*, Open/CloseBracket, Numpad*…) and accepts PgUp/PgDn.
- `crates/ui-egui/src/shortcuts.rs`: new `key_from_name` falls back to a case-insensitive match, so bindings saved by older builds (`Shift+Pageup`) start working with no migration. It is used by `parse` and by the native menu's `key_event`.

**Tests:** engine `shortcuts_normalise_and_detect_conflicts` gets PageUp/PageDown/PgDn/ArrowLeft cases. ui-egui `page_and_arrow_keys_recorded_in_the_editor_fire` round-trips editor capture through `parse` and `key_matches`, plus the legacy spellings. Not run locally: the engine lib-test target doesn't compile on main right now for an unrelated reason (`presets/mod.rs:180`, missing `export_presets`), and the ui-egui suite is too slow to build here. CI will run them.
