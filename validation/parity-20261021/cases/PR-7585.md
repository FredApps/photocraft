Fixes #7195

## Cause
`transform_to` always built a layer reference for `edit.transform` and never looked at `target`. A transform recorded against an unlinked mask, an alpha channel or the Quick Mask therefore exported without error, and when the .atn was imported and played back it transformed the layer's colour pixels instead.

## Fix
`transform_to` now returns no descriptor for `edit.transform` when it has an explicit target other than pixels. Photoshop's transform descriptor has no field for such a target, so strict export now refuses the step, and non-strict export lists it as skipped. That matches how the exporter already handles filters with a mask target.

## Verified
- Regression test `transform_with_mask_or_channel_target_is_not_exported_as_layer_transform`: fails on `main` without the fix and passes with it (`cargo test -p photocraft-engine --lib transform_with_mask_or_channel_target_is_not_exported_as_layer_transform`).
- `cargo xtask ci` passes.

## Not changed
Transforms with no target or a pixels target still export and re-import exactly as before. Quad, matrix and rect forms are still rejected, and `select.transformSelection` is unchanged. Explicit Quick Mask targets are also refused now, because whether they replay correctly depends on Quick Mask being on at playback time. No mask or channel target encoding was added to the descriptor.
