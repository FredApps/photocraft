Fixes #7884

### Problem
In Filter › Liquify, Alt+right-drag (or Ctrl+Alt-drag) changes the brush size and density (#4702), but two things were off:
- **The brush moved with the pointer.** The outline was drawn under the pointer, so it slid sideways as you dragged to resize, and so did the point the next stroke would start from. Outside Liquify, the brush tools' Alt-drag keeps the brush where it is and only changes its size, as Photoshop does in both places.
- **The press painted.** The resize started only once egui recognised the drag, a few points after the press. On that first frame the press was taken as a stroke, so every Alt+right-drag left a small dab, and a step to undo.

### Solution
`crates/ui-egui/src/liquify_ui.rs`:
- **Outline:** while the brush is being resized, it stays at the gesture's anchor (`brush_circle_at`), and so does the hover point the dialog keeps. Only its size changes.
- **Anchor:** the anchor is where the button went down (`press_origin`), so the outline doesn't jump when the gesture starts.
- **Start:** the gesture starts on the press (`is_pointer_button_down_on`), not on `drag_started`, so its first frame isn't a stroke.

The size and density mapping (`resized_brush`) is unchanged.

#7905 reports the moving outline too (its second point); it also says the gesture doesn't respond at all on Windows, which this doesn't address.

### Tests
- `alt_drag_resize_keeps_the_brush_where_it_started`, driving the real dialog (`show`) with pointer events:
  - an Alt+right press over the canvas, then a 60-point drag to the right;
  - afterwards the brush is larger, the brush point is still where the press was, and no stroke was recorded.

  Without the change it fails on both counts: the point follows the pointer, and the press leaves a stroke.
- `the_brush_outline_follows_the_pointer_except_while_resizing`: the outline position with and without a resize in progress.
