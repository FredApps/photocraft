## Pinned upstream reproduction and regression specification

The following is source material from the approved PR, not a record of testing this combined build. Test the stated scenario, values and regression names in addition to the procedure above.

Follow-up to #3869, which made palette BMPs open in Indexed Color mode. The other direction was still missing: saving an Indexed Color document as BMP went through the ordinary RGB path and wrote a 24-bit file, so the colour table was gone on reopen. The PNG exporter already had a palette branch for this.

- `export_mode_specific` now sends Indexed Color to BMP as well as PNG, through a new `encode_bmp_indexed` that writes an 8-bit palette BMP with the document's colour table. BMP has no transparency, so a transparent index is written as its palette colour and the export warns about it. A document without a usable table (none, or more than 256 colours) keeps the old RGB path.
- `bmp_palette` returned the decoder's 256-entry padding, so a 3-colour BMP reopened with 253 extra black entries. It now trims the table to the colours the header declares. (The test added in #3869 only checks the first two entries, so it still passes.)

New tests cover the codec round trip (table and pixels, row padding, bad input, header parsing) and the export/import round trip through `photocraft_io`. I did not run `cargo xtask wasm` or the corpus; the change is pure Rust on the existing `image` encoder, and CI runs both.
