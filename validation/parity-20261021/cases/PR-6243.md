## Pinned upstream reproduction and regression specification

The following is source material from the approved PR, not a record of testing this combined build. Test the stated scenario, values and regression names in addition to the procedure above.

Companion to #5697's area: a regression test for the tile-growth ordering that `keep_overlap` implements.

When a resident GPU texture's region shifts, `keep_overlap` carries the old texels over the overlap and the current update rewrites tiles inside it. The two must not race: `crates/gpu/tests/parity.rs` now grows a raster layer's tile footprint one tile per render (256 → 1024 px, 4 steps), rewrites the full extent with per-step noise each time, and compares every render against the CPU oracle on both the whole-texture and the paged compositor (`tile_growth_rewrite_keeps_fresh_texels_in_the_overlap`). If the keep copy could ever overwrite fresh tile writes, step 2 would already show stale texels — dropping the `ordered` flag makes it fail at 254/255 (measured, then restored).

A first version of this PR also moved the keep copy into the frame's encoder to save a queue submission per shifted region. That reordering is **withdrawn** per the review discussion: in the only scenario where the submission count differs (a layer whose region shifts every frame, a pure tile-coordinate remap), a controlled A/B on Vulkan (median of 7 repetitions × 300 frames) measured 6.684 ms/frame with the batching vs 6.484 ms/frame with the original separate submission — no speedup, consistent with the noisy P46 medians quoted earlier. The original deliberate separate submission is restored; this PR now only adds the ordering regression test, which passes with either submission shape by construction.
