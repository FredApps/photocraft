Fixes #5733.

### What was wrong
"When you open a file, change it and save it (via Save), it opens a Save As dialog instead." File › Save on a document opened from a flat file (PNG, JPEG, TIFF…) always went through Save As (`menus.rs`, `file.save`: `_ => app.save_dialog_flow(..)`), even when the file still held everything. Photoshop's Save writes such a file back in place, and only asks once the document has something the format can't keep (layers, transparency in a JPEG, 16-bit in a JPEG…).

### Change
`saves_flat_in_place(doc, path)` (`lib.rs`): Save writes the document's own flat file back when that file keeps the whole document:
- one plain raster layer (`plain_raster`: visible, 100% opacity, Normal, no masks, effects or blending restrictions);
- no extra channels, RGB or Grayscale;
- a format that writes the document's bit depth (`FormatCaps::depths`);
- transparency only where the format has alpha, or the layer is the Background.

Anything else keeps today's behaviour (Save As, so the original is never overwritten with less, #3806). The replay rule for recorded Saves (#3531) is unchanged.

### Test
`file_open::tests::a_flat_file_that_keeps_the_document_saves_in_place`: a PNG with one plain layer saves in place. Add a second layer and Save asks. A JPEG whose one layer isn't the Background (JPEG has no alpha) asks too. The existing `pcraft_documents_save_in_place_but_flat_files_ask` still holds: its PNG has no plain layer.
