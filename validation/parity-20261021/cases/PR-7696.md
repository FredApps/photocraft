Fixes #7671.

A recorded Stroke with `{"width":2.4,"color":"#d03060","location":"inside"}` renders at 3 px in direct execution and native action playback. Strict ATN export used nearest-integer rounding and wrote `Wdth = 2`, so reimported playback changed the image without warnings or skipped steps.

Share the existing command width normalization (finite/default 1, clamp to 1–250, round up) with a dedicated Stroke exporter. It writes the effective width to the existing integer `Wdth` field, preserving the rendered result without changing native Stroke behavior. Import, other Stroke options and the plain-event pixel-target guard stay intact. The global integer converter and other events are unchanged. This is separate from #7588's generic out-of-i32 guard.

Regression coverage:

- Compare actual pixels after direct execution, native action playback and strict binary ATN export/import/playback in 99 width/location/depth cases: seven fractional and four integer widths, inside/center/outside, 8/16/32-bit documents.
- Verify that direct 2.4 agrees with 3 and differs from 2, using a synthetic 24×18 colour/alpha fixture.
- Inspect integer `Wdth` in serialized ATN for 13 default, malformed-width fallback and boundary cases; check colour, opacity, blend mode and Preserve Transparency survive. A null parameter object also retains the command default; these 14 default/boundary cases compare direct and ATN playback pixels at 8-bit depth.
- Retain strict refusal and exact skip reporting for mask, Quick Mask and channel targets.
