## What changes in `ci.yml`



- **`merge_group:` trigger.** The queue tests each queued PR on a temporary branch (main plus the PRs queued ahead of it). Without this trigger a queued PR waits for its check forever.

- **New `ci passed` job.** It always runs last and reports red if any job failed or was cancelled, green if every job passed or was skipped. It waits for every job, including the Windows legs, `test (windows-latest)` (the gate job main added when Windows was split into two legs) and the Linux test variants. This is the one check to require: a required check that never starts stays "Expected" forever, and the per-job checks only cover part of CI (the gate job doesn't see corpus, wasm or web).

- **Merge groups choose platforms the way PRs do.** The queue starts one CI run per queued PR (see the [docs](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)), so a full Linux + Windows + web run for each one would double the load on the runners. Windows and web run when the group changes paths that need them; `main` still always runs everything.



Nothing changes until the ruleset below is on. Until then `merge_group` never fires and `ci passed` is just one more green check.

**How merging works afterwards**



- On a PR, the button becomes **Merge when ready**: click it, and the PR joins the queue and merges by itself when its run is green. If the run fails, it drops out of the queue with the failure shown on the PR.

- CLI and AI mergers: `gh pr merge <number>` adds the PR to the queue (no `--squash`/`--merge` needed). Don't use `--admin` routinely, because it bypasses the queue.

- To turn it off again: set the ruleset's enforcement to Disabled.



## Trade-offs



- The queue adds one CI run per merged PR on top of the PR's own runs. In exchange, nobody has to merge main into a branch just to re-check it, and main stops breaking from untested combinations. Build concurrency limits how much it can take from the runners at once.

- `main` still runs full CI after each merge, because only main's runs save the build cache that PR and queue runs restore.
