Fixes #6549.



With Object Finder on and Sample All Layers off, hovering over a spot where the active layer has no pixels (for example a new empty layer above the photo) showed nothing. The click already reports this as an error ("the active layer is empty; set sampleAllLayers..."), but the hover gave no reason.



Changes:



- `smartselect_cmds`: the check behind the click error moves into a public `empty_sampled_area(doc, layer, all_layers, area)`. `check_sampled_pixels` (the `select.object` click and rect paths) now calls it and returns the same error text as before.

- `object_finder::update`: before it looks for an object, it runs the same check on the pixel under the pointer. If the sampled layer has no pixels there, it starts no lookup and returns a hint: "The active layer has no pixels here — turn on Sample All Layers or select a layer with pixels".

- `object_finder::draw`: puts that hint in the status bar as a normal message, not an error. It clears the hint when the pointer moves to a spot that has pixels, and it never clears other status messages.

- The hint is translated in every complete catalog, so `every_tl_literal_is_translated` still passes. It uses each catalog's existing name for "Sample All Layers".

- `docs/ui-parity.md`: the Object Finder row describes the hint.



Nothing changes with Sample All Layers on, or when the active layer has pixels under the pointer.



Test: `hovering_an_empty_active_layer_gives_a_hint_not_silence` adds an empty layer over the disc document. The hover returns the hint, starts no lookup and shows no overlay. With Sample All Layers on, there is no hint and the disc is highlighted.
