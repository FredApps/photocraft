Fixes #7946

### Problem
Filter › Stylize › Emboss (`filter.stylize.emboss`) records and plays in PhotoCraft's own Actions, but the `.atn` writer had no Photoshop event for it:
- `actions.save` refused the action ("has no Photoshop equivalent");
- with `skipUnsupported` it left the step out, so the saved action silently lost the relief.

Photoshop has the filter, so the step has a Photoshop form.

### Solution
`crates/engine/src/atn_cmds.rs`: Emboss joins the mapped events as Photoshop records it:
- the event is `Embs`;
- `Angl` ↔ `angle`, `Hght` ↔ `height` and `Amnt` ↔ `amount`, all plain integers (Photoshop's Emboss dialog takes whole degrees, pixels and percent).

The same table entry works both ways: saving writes `Embs`, and loading a Photoshop action with an Emboss step gives `filter.stylize.emboss` back. Like the other pixel filters, a step recorded against a layer mask is still not exported as a pixel filter.

### Tests
`atn_cmds::tests::emboss_saves_as_photoshops_event_and_loads_back`:
- an action with `filter.stylize.emboss {angle: 130, height: 1, amount: 70}` (the reporter's step) saves with nothing skipped;
- the file holds an `Embs` event with `Angl` 130, `Hght` 1 and `Amnt` 70 as integers;
- loading it gives the same step and params.

It fails without the change: the save errors with "no Photoshop equivalent".
