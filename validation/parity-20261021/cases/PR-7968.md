## Summary

Fixes #7236. A recorded `layer.groupLayers` step with an explicit layer now exports its target the way every other layer reference in this file does, and the import restores it; the implicit form (group the current selection) survives unchanged.

The issue's reproduction: a recorded step `["layer.groupLayers", {"layer": "A", "name": "Group"}]` groups A when replayed directly, but after a strict `.atn` round trip the exported descriptor had `From: target_ref("Lyr ")` — the target layer, not A — and the re-imported step was `{"name": "Group"}`, so playback grouped the selection (B and C) instead.

## The change

- `make_to`: `layer.groupLayers` exports `From` through the existing `layer_ref` helper — a `layer` param becomes a named `Lyr ` reference, its absence keeps the previous `target_ref("Lyr ")` form byte for byte (crates/engine/src/atn_cmds.rs:1153).
- `make_from`: the `layerSection` branch reads the `From` reference it already checked for and restores `{"layer": name}` through the existing `layer_target` helper; no `From` still imports as `layer.new.group` (crates/engine/src/atn_cmds.rs:1124).

Both helpers are the same ones the rest of the file uses, so the descriptor holds the standard named-reference form our `.atn` bytes already carry for other layer commands; import needed no new code paths.

## Boundary

Photoshop-authored `From` references we cannot restore (a zero-based index) keep the old implicit import — the group lands on the current selection at playback, exactly as before this change; the exporter never writes those forms. The target-reference form (`Trgt`) also stays implicit, which is what the issue's passing control needs.
