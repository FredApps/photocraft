### What was wrong
In Photoshop, **Filter › Distort › Displace** asks for the displacement map file (a PSD) after you click OK. PhotoCraft's dialog is generated from the command spec. It offered the map only as *Map Document* (a dropdown of open documents) or *Map Path* (a plain text field to type a path into). OK with neither set ran without a map, and no file picker ever appeared. That's exactly what the reporter describes.

### Change
- `filter_dialog::needs_displace_map`: Displace confirmed with no map document and no (non-blank) path.
- `filter_dialog::ask_displace_map`: opens the open-file picker in the last-used folder. On a choice it runs Displace with the dialog's values plus `mapPath`, through the same `smart_ui::confirm_command` path as OK (so editing a Displace smart filter works too), then remembers the values and resumes a playing action. Cancel applies nothing.
- `dialogs::confirm` calls it before running the command.
- In the browser the picker hands over contents, not a path the filter can read. There it reports that the map must be opened as a document and picked as *Map Document*.

### Test
`filter_dialog::tests::displace_asks_for_its_map_after_ok`: OK with no map asks once and Displace runs with the chosen PNG (one history step). A cancelled picker applies nothing. A map path or map document already set skips the picker. Not built or run locally; CI runs it.
