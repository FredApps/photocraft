Fixes #6957



### Problem

A camera raw that PhotoCraft develops opened without its EXIF, so File › File Info › Camera Data was empty: no make, model, date taken, exposure, f-stop, ISO or lens. The raw file carries all of them in its standard TIFF/EXIF directories. `raw.rs` noted that developed raws "carry no EXIF", and File Info reads Camera Data from the document's EXIF block.



### Solution

- **`crates/codecs/src/lib.rs`, new `raw_exif(bytes)`:** the EXIF block of a camera raw built on TIFF: IFD0's descriptive tags (make, model, date, software, artist, copyright) and the Exif and GPS directories. It is the block a TIFF opens with (`tiff_exif`), values copied as bytes and bounded as for TIFF, with two differences for a raw:

  - **Panasonic RW2** is read too. Its classic TIFF header has 0x55 (`IIU\0`) in place of 42 (`File::parse_raw`, used only here).

  - **PixelXDimension and PixelYDimension are left out.** In a raw they give the sensor's or the preview's size, not the developed image's.



  `None` when the file isn't built on a classic TIFF stream or has neither directory.

- **`crates/io/src/raw.rs`, `developed_document`:** the developed image's EXIF is the raw's. This covers the default open and a Camera Raw re-develop.

  - Covered: NEF, ARW, CR2, DNG and RW2, the formats the issue found with empty Camera Data.

  - Not covered: CR3 and RAF aren't TIFF streams. CR3 previews are #5922.

- **Orientation:** none to undo. The block never carries Orientation (IFD0's structure, resolution and orientation tags aren't copied), and the developed image is already upright. The upright-preview note was updated to say so.



Saving keeps the EXIF as for any other document, with the image's own resolution and orientation.



### Tests

`crates/io/tests/raw.rs`:

- **`a_developed_raw_keeps_its_exif`** (synthetic CR2 with Orientation 6): the developed document's EXIF reads back as Canon / Canon EOS Synthetic, exposure 1/100 s. It carries no orientation, and the document is still the upright 16 × 48.

- **`a_developed_rw2_keeps_its_exif`** (synthetic RW2 with an Exif directory holding exposure and pixel dimensions): the EXIF reads back as Panasonic / DC-Synthetic, 1/60 s. Its Exif directory has ExposureTime but no PixelXDimension or PixelYDimension.



Both fail without the fix: the developed document has no EXIF.
