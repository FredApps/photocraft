### Problem
In Filter › Adaptive Wide Angle…, right-clicking a constraint line deleted it at once. Photoshop instead opens a menu on the constraint to choose its orientation or delete it ([Adobe's Adaptive Wide Angle help](https://helpx.adobe.com/photoshop/using/adaptive-wide-angle-filter.html)). `docs/context-menu-parity.md` lists this as a P1 behaviour mismatch.

### Solution
`crates/ui-egui/src/wide_angle_ui.rs`:
- **The menu.** Right-clicking a constraint opens `constraint_menu` with Free, Horizontal and Vertical (the current orientation checked) and Delete. The menu uses the same hit test as before: the constraint whose curve passes within 10 pt of the click.
- **Away from a constraint.** A right-click away from every constraint opens nothing and deletes nothing.
- **Labels.** The menu reuses the labels the constraint list in the panel already shows ("Free", "Horizontal", "Vertical", "Delete"), so the two read the same. Photoshop's Arbitrary angle isn't offered because the solver has no arbitrary-angle constraint yet.
- **Control channel.** It gains `"orient": {"index": i, "orientation": "free|horizontal|vertical"}` beside `add` and `remove`, so agents can do what the menu does. A missing or out-of-range index is an error.
- **Hint.** The dialog's hint no longer says "right-click to delete". It now reads "…; right-click a constraint to change or delete it." The 20 catalogs that carried the old hint get the new key, with only its last clause rewritten, so `complete_menus` stays satisfied.

`docs/context-menu-parity.md` marks the row done, except Arbitrary.

### Tests
- `right_click_on_a_constraint_opens_its_menu` drives the dialog with real pointer events through egui_kittest:
  - right-click the constraint, choose Horizontal: the constraint is kept and turns horizontal;
  - right-click away from it: no menu, nothing deleted;
  - right-click it again, Delete: it is gone.
- `orient_sets_a_constraint_orientation` covers the control-channel op and its bad indices.
