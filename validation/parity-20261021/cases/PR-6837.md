Closes #6540



The Hue track was pastel because `widgets::hue_stops` built its stops with `Hsva::new(h, 0.85, 1.0, 1.0).to_srgb()`: 0.85 saturation, and `Hsva` is linear, so every stop was washed out and hues bunched up. The Colorize spectrum bars had the same linear-light spacing.



- New `widgets::hue_color(deg)`: the fully saturated hue built on sRGB values with the existing `color_picker_ui::hsv_to_rgb` (0 is 255,0,0, 60 is 255,255,0, ...).

- `hue_stops` (Hue slider in Hue/Saturation, Camera Raw, Color panel) now uses it at full saturation.

- `adjust_editors.rs` drops its own linear `hue_color` and uses the shared one (Saturation track end, input spectrum bar). The adjusted spectrum bar now samples its input hues with `hsv_to_rgb` too, so both bars are spaced evenly by hue angle.

- `camera_raw_ui.rs` drops its second copy of `hue_color` (which capped channels at 220) and uses the shared one for the HSL band tracks.



The Lightness track is left alone; that is #6539.



Test: a new unit test in `widgets::tests` checks that the 13 stops have the track ends and the six 60-degree stops at exactly (255,0,0), (255,255,0), (0,255,0), (0,255,255), (0,0,255), (255,0,255), and that `hue_color` returns the same. On main the first stop is (255,125,108)-like pastel, so it fails.
