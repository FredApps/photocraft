## Pinned upstream reproduction and regression specification

Image › Mode › Indexed Color and Save for Web build their Perceptual, Selective and Adaptive palettes on one core, and a 24 MP photo took 4 to 5 s (14 s on a noisy image). This makes it about 8× faster, and every palette comes out bit for bit the same.

### Root cause
- `median_cut` re-measured the extent and weight of **every** box on every split, though only the two new boxes change. With up to 256 boxes over millions of points, that was most of the time.
- Each split sorted with a comparison `sort_by`.
- `histogram()` did a SipHash `HashMap` insert per pixel, and the k-means nearest-centre search was serial.

### Fix (all in `crates/algo/src/quantize.rs`)
- `median_cut` caches each box's (axis, score) in lockstep with `boxes` (same `swap_remove` and pushes) and scores only the two new boxes, with the same expressions, so the box chosen at each step is unchanged.
- Boxes of 256 or more points sort with a stable LSD radix sort on a key whose unsigned order is exactly `f32::total_cmp` order. Stable like `sort_by`, so ties keep their order. Smaller boxes keep `sort_by`.
- `histogram()` packs opaque pixels into one `u32` each, `par_sort_unstable`s them and counts the runs (integer counts, so the order of work cannot change the result; no per-thread tables).
- k-means finds the nearest centre for every point in parallel, then adds the f64 sums **sequentially in the original order**, so float rounding is unchanged. The Lab conversion of the histogram is a parallel map that keeps order.
- `to8` drops the per-channel `roundf` call: truncate, then add one when the exact remainder is at least 0.5 (same as `f32::round` on 0..=255, NaN gives 0 in both).
- wasm keeps the serial paths, following the `cfg(target_arch = "wasm32")` pattern `liquify.rs` uses.
