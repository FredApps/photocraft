### What was wrong

The report says the Move tool used to show the same "how far I've moved it" tooltip as Ctrl+T, and doesn't in 0.9.0. In the code, no release (0.6.0 through 0.9.0, and `main`) ever drew a readout for a plain Move-tool drag. The only ΔX/ΔY readout is Free Transform's (`transform_tool::live_readout`, `Hit::Inside`). The Move tool reaches it only when a drag starts on one of its transform-control handles or the rotation band, which opens a Free Transform session. A drag *inside* the box, or with Show Transform Controls off, is an ordinary Move drag and showed nothing. So the reporter most likely saw it through Free Transform. Either way, Photoshop shows ΔX/ΔY for an ordinary Move drag, and PhotoCraft didn't.

### The change

- `move_ui::offset_readout`: the ΔX/ΔY strings for the Move drag in progress. It uses the same whole-pixel offset (`drag_offset`) that the live preview shows and the release commits through `layer.translate`. It returns `None` until the pointer has moved, so a click shows nothing.
- `canvas::draw_drag_preview` draws it at the pointer (`"move-readout"`), before the early return for selected-pixel drags, so it shows both when dragging a layer and when dragging selected pixels.
- It goes through `draw_value_readout`, so **Preferences › Tools › Show Transformation Values** hides it, like the marquee, crop and Free Transform readouts. Same `ΔX:`/`ΔY:` labels and `N px` format as Free Transform's offset readout.

### Test

`move_ui::tests::a_move_drag_reads_out_the_offset_it_will_commit`: no readout before the drag or right after the press; a drag to (+10.4, −3.2) reads `10 px` / `-3 px`, the offset the release commits; and nothing after the release.
