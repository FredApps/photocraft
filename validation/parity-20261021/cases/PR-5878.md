Fixes #5647.

### What was wrong
Pressing a tool's letter again cycled through its group (V: Move → Artboard, B: Brush → Pencil → …). In Photoshop the plain letter keeps the tool, and **Shift+letter** cycles ("Use Shift Key for Tool Switch", on by default).

PhotoCraft already behaves that way when the preference is on (`shortcuts.rs`), and #3528 (2026-10-12, first released in 0.8.2) made it on by default. But the preferences file stores **every** key, chosen or not. Every install that ran an earlier build has `"useShiftKeyForToolSwitch": false` saved, the old default, so the new default never reached existing users. The existing test only covers a file *without* the key.

### Change
`Session::load_prefs_json`: a settings file older than version 2 that stores `useShiftKeyForToolSwitch: false` drops that key, so it takes the new default (on). `prefs_value` now writes `"version": 2` (`PREFS_VERSION`), so a user who turns the preference off from now on keeps it off. This follows the existing appearance-mode migration in the same function.

One trade-off: someone who deliberately turned the preference off on 0.8.2–0.9.0 (when the file still said version 1) gets it back on once, and can turn it off again.

### Test
`prefs::tests::old_settings_files_take_the_shift_key_tool_switch_default`: files without a version and with version 1 storing `false` load with the switch on, and other Tools settings are kept. A preference turned off and saved now writes version 2 and stays off when reloaded. Not built or run locally; CI runs it.
