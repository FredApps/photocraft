## What

Fixes #6958 — File Info showed a stored exposure of 0.031714 s (about 1/32 s) as `0.03 s`.

`exposure_text` in `crates/engine/src/file_cmds.rs` used the `1/n` form only when `1/t` was within 1 % of a whole number. For exposures longer than 1/50 s that tolerance is smaller than half a denominator step, so most real camera values (phones store 1/32 as 31714/1000000) fell through to `short_num(t, 2)` and lost a digit or two.

Now:

* sub-second exposures use the **nearest whole denominator** when it is within 5 % of the stored value — `0.031714 s → `1/32 s`, `0.0215 s → `1/47 s` (the issue's fixtures), while `0.4 s` still renders as `0.4 s`, not `1/3 s`;
* the decimal fallback for sub-second times keeps **three significant digits** instead of two decimals (`0.2731 s → `0.273 s`), per the issue's suggestion;
* exposures ≥ 1 s are unchanged.

Tests: extended `camera_data_formats_like_photoshop_and_falls_back_to_xmp` with the fixture values and the fallback. `cargo test -p photocraft-engine --lib` (1702 passed), clippy clean, `cargo xtask layers` OK.
