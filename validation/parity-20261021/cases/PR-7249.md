Fixes #7194

### Problem
When exporting recorded actions containing `select.rect` with `mode: "add"` or `mode: "remove"`, `atn_cmds::set_to` previously ignored the `mode` parameter and mapped the step into a standard marquee replace `set` event (`Elps` or `Rctn`). When replayed in Photoshop or imported back, the step would silently replace the active selection instead of adding to or subtracting from it, potentially corrupting selection workflows.

### Solution
- Updated `select.rect` in `atn_cmds::set_to` to check `p["mode"]`. Only `None` and `Some("replace")` produce an ATN descriptor.
- Non-replace modes return `None`, causing strict export (`actions.save`) to return an unrepresentable error as intended, or when `skipUnsupported: true` is supplied, record the step in `skipped`.
- Added a regression test `select_rect_mode_strict_export_rejects_unrepresentable_modes` covering default, replace, add, remove, and `skipUnsupported` modes.
