Fixes #7247

## Cause
`apply_image_to` turned `image.applyImage` into an `AppI` descriptor without looking at the optional blending mask (`mask` or flat `maskChannel`), so the mask was silently dropped. Because the export still succeeded, the converted step applied to the whole layer instead of only the masked area.

## Fix
`apply_image_to` now returns no descriptor when an effective blending mask is set (a mask channel other than none or empty). Strict export now fails for these steps, and lenient export reports them as skipped instead of writing a wider edit. Unmasked forms, and masks with channel `none`, export as before.

## Verified
- Regression test `apply_image_with_blending_mask_is_not_exported_without_its_mask`: fails on `main` without the fix and passes with it (`cargo test -p photocraft-engine --lib apply_image_with_blending_mask_is_not_exported_without_its_mask`).
- `cargo xtask ci` passes.

## Not changed
No `.atn` descriptor mapping for the blending mask was added, so masked Apply Image steps are refused rather than converted. The normalization of flat source fields (#7197) and the destination layer-mask target (#6780) are not changed.
