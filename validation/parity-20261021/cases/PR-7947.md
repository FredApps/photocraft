## Problem

With served fonts (`fonts/manifest.txt`, #1875), hovering a row in the font menu previews that family on the canvas, and for a family that isn't fetched yet the preview asks the host for the whole family (`type_font_preview::set` → `served::request`). Since #5222 that preview reaches the canvas from the options bar too, so moving the pointer down the menu downloads every family it passes over.

Measured in Chrome on a web build of main `03d0c7e3` serving 1,700 Google Fonts families: moving the pointer over 10 rows, 60 ms on each, fetched 15 font files from 10 families, 3.5 MB, in under a second. We embed the web build in a sandboxed iframe (opaque origin), so nothing is cached between sessions and this repeats every time.

## Change

- A family that isn't installed previews (and so is fetched) once the pointer has rested on its row for 0.25 s (`HOVER_FETCH_DELAY`). Moving to another row starts the wait again; while waiting, `request_repaint_after` brings the frame that previews it.
- Installed fonts (bundled, system, or served and already fetched) preview at once, as before. Picking a font (a click, or the arrow keys) still fetches it at once.
- Tests in `type_font_preview.rs`: passing over rows asks for nothing and a rest previews the family (`a_served_family_is_asked_for_only_once_the_pointer_rests_on_its_row`); an installed family previews on the first frame.

A note on large catalogs: at ~1,700 families, laying out every row each frame the menu is open is noticeable too. #884 lays the rows out with `ScrollArea::show_rows`, and #7821 wraps them in a `ScrollArea`, where `show_rows` would cover it. This PR leaves the rows alone, so it doesn't conflict with either.
