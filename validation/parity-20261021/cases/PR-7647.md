Closes #6593.

After a Pen path was finished, with Escape or ↩, a Pen click on one of its endpoints started a new subpath at that spot. Photoshop 2025 carries on drawing the same path from there. To check, I drew two anchors, pressed Escape, then clicked the last anchor and placed another point: Photoshop extended the path to three anchors.

`vector_ui::pen_down` only looked at the path being drawn. With no path in progress, every press started a new one, and `commit_path` added it to the selected path as another subpath.

### Change

- **Resuming:** with no Pen path in progress, a press on the first or last anchor of an open subpath of the path a new one would join loads that subpath into the Pen (`resume_at`). That path is the one selected in the Paths panel, else the work path.
  - From the last anchor it continues as it was.
  - From the first anchor it is reversed, with in and out handles swapped, so drawing carries on past that end.
  - The press then acts on the Pen's last anchor as before, so a drag from it pulls out the next segment's handle.
- **Committing:** `PenPath::resumes` records which subpath was picked up. `commit_path` writes it back in place with `path.set` (`with_resumed_subpath`) as one History step, instead of adding a second subpath. Only that subpath's anchors and closing change, so its path operation is kept. The draft remembers its document and the subpath as it was. If either changed before the commit (another document, or the path edited meanwhile), the drawing is added as a new subpath instead, so nothing is overwritten. Closing on the far anchor closes that subpath.
- **Unchanged:** Shape mode and a targeted vector mask, which take new paths, never resume. A press anywhere else starts a new subpath as before.

### Tests

- New: `the_pen_carries_on_an_open_path_from_either_end` (pen_variants_tests) checks:
  - Extending from the last anchor gives one subpath of 3 anchors, in one History step.
  - From the first anchor, the subpath is reversed and continues past it.
  - A press elsewhere still adds a second subpath.
  - Closing on the far end of a resumed subpath closes it.

  It fails without the fix: the old code made a second subpath.
- New: `a_resumed_subpath_keeps_its_operation_and_a_stale_draft_adds_a_new_one`. A Subtract subpath stays Subtract when carried on; a draft whose path was replaced meanwhile lands as a second subpath.
- `cargo fmt`, `clippy -D warnings`, the ui-egui suite (3,194 tests), `cargo xtask wasm` and `cargo xtask layers` pass.

### Verified in the app

On macOS 27 with a release build, side by side with Photoshop 2025:

- **Before the click:** two Pen anchors, then Escape. The path stays (History: Work Path), as in Photoshop.
- **The resume:** a click on its last anchor, then a new point. The line carries on from that anchor, with one more History step.
- **The result:** `path.info` over the control channel shows a work path of one subpath with three anchors, as in Photoshop.
