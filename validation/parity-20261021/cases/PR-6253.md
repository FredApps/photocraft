## Pinned upstream reproduction and regression specification

Fixes #6232.

`premerges_layer()` left Normal layers out, on the idea that Normal gives the same result whether the interior effects paint over the merged layer or over the layer alone. That only holds for Normal effects. At Fill 0 % the layer's own buffer is transparent, so a Soft Light Color Overlay blended against nothing and came out as its plain colour, which then went over the background in Normal. Photoshop blends it against what shows through the layer. Now a Normal layer merges first, the same path #4231 added for #3996, when one of its enabled interior effects (overlays, satin, inner glow/shadow, inside stroke, inner bevel) blends in a mode other than Normal. The GPU planner picks this up too because it uses the same predicate. Thanks to @sageford for the source analysis in the issue, which pointed straight at the right place.

I kept other Normal layers off the merge path on purpose. With a half-transparent backdrop under a layer below 100 % fill, the merged layer goes over a backdrop that already contains it, so the backdrop counts twice: red at 50 % under blue at fill 50 % with only a drop shadow ends at alpha 0.876 instead of 0.75. The second test pins that down. Non-Normal layers have the same double count today (since #4231), and so now does a Normal layer with a non-Normal interior effect, but only on a half-transparent backdrop. Fixing it means finishing the merge with a lerp by the shape's alpha, and the outside-stroke share would have to change with it, on CPU and GPU. I'd rather keep that for a follow-up and am happy to open one, or to switch approach if you prefer.
