## Problem

On a Linux system without Windows fonts, text in an imported SVG is dropped. For example, Fedora 44 has neither Arial nor DejaVu Sans. The import then only warns "SVG: nothing to draw (an empty drawing)", although hundreds of fonts are installed. Because of this, `crates/io/tests/svg.rs` `text_becomes_outline_shapes_or_warns_without_a_font` fails on Fedora 44 on `main`.

## Cause

The SVG importer shapes text with its own `usvg::fontdb` database (`svg.rs` `fonts()`), not with the Fontconfig path of `photocraft-text` (#2961). fontdb does not know Fontconfig's aliases, and it maps the generic families to Windows fonts: `sans-serif` to Arial, `serif` to Times New Roman, `monospace` to Courier New.

So on such a system every family of a usual `font-family="Arial, Helvetica, sans-serif"` misses, including the generic one, and so does the `serif` default that usvg appends. usvg then drops the text chunk while parsing.

The warning from #3168 only fires when the font database is empty, so here the user just gets "nothing to draw".

```
$ fc-match 'DejaVu Sans'; fc-match Arial; fc-match sans-serif
NotoSans-Regular.ttf: "Noto Sans" "Regular"
LiberationSans-Regular.ttf: "Liberation Sans" "Regular"
NotoSans-Regular.ttf: "Noto Sans" "Regular"
```

Official builds are affected too: the bundled craft fonts are in the database, but no generic family points at them.

## Fix

`resolve_generic_families` points each generic family at a font the database holds, the way a browser falls back. In order of preference:

1. the system's choice, when the database has it (`fc-match <generic>` on Linux native; nothing elsewhere);
2. the first installed stand-in:
   - Liberation and Croscore, which are metric-compatible;
   - DejaVu and Noto;
   - the bundled Inter or JetBrains Mono;
3. the sans-serif choice;
4. any installed font.

A generic whose font is already installed is left alone, so systems with Arial and friends behave as before. `fc-match` runs at most once per process, when the font database is first loaded, which already only happens for drawings with text.

## Tests

- `text_in_missing_fonts_falls_back_to_an_installed_one`: the database holds only the bundled `assets/fonts/Inter-Regular.ttf`, with no system fonts and no Fontconfig. `Arial, Helvetica, sans-serif`, `Times New Roman`, `Courier New, monospace`, `cursive` and `fantasy` all produce the text layer. Without the fix it fails with the same "nothing to draw".
- `generic_families_point_at_installed_fonts`:
  - every generic resolves to an installed font;
  - the system's choice wins when installed;
  - an installed generic stays;
  - an empty database is left alone.
- `crates/io/tests/svg.rs` now passes on Fedora 44 (16/16). Checked by hand with `photocraft-cli convert` on an SVG with `Arial, Helvetica, sans-serif` and `Times New Roman, serif` text: both come out as type layers, in Noto Sans and Noto Serif.
