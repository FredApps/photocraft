## Pinned upstream reproduction and regression specification

Closes #7669 and #7670. **#7671 (Stroke) is not in this change** — see below.

`Kind::Long` wrote its param through `long()`, which rounds:

```rust
fn long(v: f64) -> D {
    D::Integer(v.round().clamp(f64::from(i32::MIN), f64::from(i32::MAX)) as i32)
}
```

Photoshop's field really is an integer, so a fractional setting cannot be written — but rounding it put a different edit in the file than the one recorded, with `skipped` empty and nothing to say so. Measured through `actions.save` and back:

| step | recorded | in the file | read back |
| --- | --- | --- | --- |
| `filter.pixelate.crystallize` | `cellSize: 5.4` | `ClSz 5` | `cellSize: 5` |
| `filter.distort.ripple` | `amount: 81.4` | `Amnt 81` | `amount: 81` |

(The first row is the new round-trip test run against `main`: `left: Some(5.0), right: Some(5.4)`.) The reports measure what that does to the pixels — 385 to 583 differing colour components at every bit depth.

### Why Stroke is out

`edit.stroke` normalises the width itself:

```rust
// crates/engine/src/extra_cmds.rs:137
let width = p.get("width").and_then(Value::as_f64).filter(|w| w.is_finite()).unwrap_or(1.0).clamp(1.0, 250.0).ceil() as usize;
```

`.ceil()`, so `width: 2.4` renders at **3** — an integer field can hold that exactly, and refusing the step would throw away something expressible. On `main` it renders at 3 and exports `Wdth 2` with `skipped` empty, which is wrong in both directions this PR could have gone. @PerchAnton's #7696 normalises it instead, which is the only approach that reproduces what the user saw. My first version refused it; that was my mistake.

### What changed

The refusal is a field's own kind, `Kind::LongExact`, carried by the two fields whose command uses the setting as written:

- Crystallize's `ClSz` — `cell_size: f(p, "cellSize", 10.0).clamp(3.0, 300.0)`, no rounding
- Ripple's `Amnt` — `amount: f(p, "amount", 100.0).clamp(-999.0, 999.0)`, no rounding

`long_exact` returns `None` for a value such a field cannot hold — a fraction, or a magnitude past `i32` — and `fields_to` passes that up. The step then takes the path a step with no Photoshop equivalent already takes: strict export names it and fails, `skipUnsupported: true` leaves it out and lists it in `skipped`.

The first version sent **all 26** `Kind::Long` fields through `long_exact` on the strength of three reports, one of which turned out to need the opposite. The other 24 keep `long()` until someone has read each against its command.

Refusing, rather than exporting a near miss, is what the rest of this file does: `pixel_target` already refuses a filter step aimed at a mask because "Photoshop's descriptor for a plain event has no field for a mask … so such a step can't be exported faithfully".

The strict error now reads "can't be written as a Photoshop step: it has no equivalent event, or a setting its event can't hold", since both cases arrive there.
