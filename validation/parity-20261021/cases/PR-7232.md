## Summary

Fixes #7185.

When an action is recorded in PhotoCraft, selecting a layer records `layer.select {"name": ...}` (as introduced in #2441 for portable layer referencing). However, `select_to` in `crates/engine/src/atn_cmds.rs` only looked for the `"layer"` string parameter.

As a result:
- In strict `.atn` export, `actions.save` failed with an error claiming `layer.select` has no Photoshop equivalent.
- In the desktop UI (which uses `skipUnsupported: true`), the layer selection step was silently dropped from the exported action, causing subsequent recorded commands to act on whichever layer was previously active.

## Changes

1. **`select_to`**: Support both `name` and `layer` targets: `jstr(p, "name").or_else(|| jstr(p, "layer"))?`.
2. **`occurrence` handling**: Explicitly reject duplicate-name `occurrence` targets (`p.get("occurrence").is_some()`) because Photoshop name references cannot faithfully distinguish duplicate layer names; this avoids silently selecting the wrong layer on playback.
3. **Regression Tests**: Added `recorded_layer_select_exports_to_atn` in `crates/engine/src/atn_cmds/tests.rs` covering normal action recording, strict `.atn` save, `skipUnsupported` behavior, and duplicate occurrence rejection.
