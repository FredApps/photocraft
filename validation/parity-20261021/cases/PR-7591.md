## Pinned upstream reproduction and regression specification

Fixes #7540, fixes #7541, fixes #7542, fixes #7543, fixes #7544, fixes #7545, fixes #7546.

Strict `.atn` export wrote these steps without an option their descriptors have no field for, so they replayed differently. As the tickets allow, they're now refused rather than changed: strict export fails with the step named, and an export with `skipUnsupported` lists it as skipped. Nothing about Photoshop's descriptor keys is assumed.

- **Feather, Contract, Smooth, and Expand (which has the same flag):** `applyAtCanvasBounds: true` changes how the selection is padded at the canvas edge, but the events carry only the radius (#7540, #7541, #7542). The event table gains an `uncarried:` list of such flags per event, which keeps it general for the next one.
- **Paint Bucket with `contents: "pattern"`:** Fill's `Pttn` names no pattern and has no placement, so the following replayed with the current pattern at its defaults (#7543, #7544, #7545, #7546). They're now refused:
  - an explicit `pattern`;
  - a `scale` other than 100;
  - an `angle` other than 0;
  - a `phase` other than `[0, 0]`.

Defaults still export (`applyAtCanvasBounds: false`, a pattern bucket with no pattern, scale 100, angle 0 and phase `[0, 0]`), and the modify steps round-trip as `{"radius"}`.

## Test

`canvas_bound_modify_and_placed_pattern_bucket_refuse_strict_export`:
- each of the four modify events with `applyAtCanvasBounds: true` fails strict export; with `false` it exports and imports as `{"radius": 2}`.
- a pattern bucket with a pattern, scale, angle or phase fails strict export; with none of them, or all at their defaults, it exports.
