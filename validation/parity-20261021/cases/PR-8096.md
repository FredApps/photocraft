TL;DR: three small fixes CodeRabbit found in PRs from the #8095 batch. A typo in `baseline` no longer clears superscript, an Indexed/Bitmap save warns whenever flattening loses a layer, and ABR import no longer keeps a second copy of a file of up to 1 GiB.

#8095 merged the batch at `bc5e4d4c8`. This fix-up was pushed to #8084 after that, so it is not on main yet. This PR is only that commit, on top of main at `b097800e7`.

## Changes

- **#5807, `type_cmds.rs`:** an unknown `baseline` value (e.g. `"superscipt"`) reset superscript or subscript to Normal. It is now a BadParams error in `type.setStyle`, `type.edit` and `type.create`, and `apply_char_props` leaves the style unchanged for it. `null` is still ignored.
- **#4816, `palette_map.rs`:** Indexed and Bitmap have no layers in Photoshop, so the save stays a flat file, as Multichannel already does. Until now the save only warned for two or more layers. It now warns whenever flattening loses something: more than one layer, or a single layer that is hidden, masked, clipped, below full opacity, not Normal, has effects, or is not a pixel layer.
- **#7180, `preset_import_cmds.rs`:** the apply closure cloned all params, including a base64 `data` string of up to ~1.3 GiB. It now gets only `replace` and `select`.

## Testing

- New tests: `unknown_baseline_is_rejected_and_keeps_the_style` and `indexed_save_warns_whenever_flattening_loses_a_layer`. Both fail without the fix. The existing `select: true` ABR test covers the apply params.
- Locally (Windows): fmt, clippy `-D warnings` on engine and io, `photocraft-io` and `photocraft-engine` lib and integration tests, `panic_hunt --ignored`, and a wasm check of both crates all pass.
