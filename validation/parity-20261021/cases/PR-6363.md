Addresses point 1 of #321 ("I expected to set working space per document on document creation"). It's Photoshop's New Document › Advanced Options › Color Profile.

## Change
- **Engine** (`file.new`): new optional `profile` param: `"working"` (default, unchanged behaviour), a built-in id, or a path to an .icc file. It's resolved with `ColorState::resolve` and must match the mode's colour space (`mode_space`). Both checks run before the document opens, so a bad profile opens nothing. `validate_new_params` accepts the key, and the params doc lists it.
- **New Document dialog** (`new_doc_ui.rs`): a **Color Profile** menu under Color Mode. It lists "Working: <profile>" first, then the built-in and installed profiles of the mode's space. Changing the mode drops a profile chosen for the old space. Both labels reuse strings that are already translated in every catalog.

The other points in #321, with my notes:
- (2) The document's profile can already be shown in the status bar (its Show menu › Document Profile).
- (3) View transforms are #564 (OCIO).
- (4) Color Settings, Assign Profile and Convert to Profile sit in the Edit menu in Photoshop too, so they stay there for parity.

## Tests
- Engine: `file_new_tags_the_document_with_the_chosen_profile` covers Adobe RGB on RGB and Coated CMYK on CMYK, checks that `working` and the default leave the document as before, and checks that an unsuitable, unknown, empty or non-string profile errs without opening a document.
- UI: `color_profile_menu_lists_the_profiles_of_the_modes_space` checks the menu per mode, and checks that every built-in entry the menu offers is accepted by `file.new`.
