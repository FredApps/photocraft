Fixes #6563.

## Cause
`Compositor::sync` (`crates/gpu/src/lib.rs`) created each `pc_compose_layer` page texture with a bare `device.create_texture`. The new page's bytes weren't checked against the resident budget (eviction ran only after each cell), and an Out of Memory went uncaptured, so every later texture in the pass was invalid and the error reached the health watcher.

## Fix
- Before creating a page, `evict_residents` drops least recently used pages (never the current cell's, never the page being replaced) so its bytes fit the budget.
- Creation runs in the existing `first_error` error scopes on native. On Out of Memory every page the current cell doesn't use is dropped and creation is retried once.
- If it still fails, the cell draws nothing and the refresh returns `Unsupported(OVER_BUDGET)`: that refresh goes to the CPU and the next one tries the GPU again. The captured error no longer reaches the health callbacks, so it doesn't mark the device faulted. Turning *uncaptured* errors into non-permanent faults stays with #6564.
- WebGPU (wasm) reports errors asynchronously, so there creation is unscoped as before (pre-admission eviction still applies).
- `OVER_BUDGET` moves to `photocraft-gpu`; `ui-egui` re-exports it, so the existing GPU Memory Full notice shows for this case too.

## Tests
- New unit test `layer_pages_are_admitted_by_evicting_least_recently_used_first` covers the pure LRU admission function `lru_victims` (fit, partial eviction, zero budget, overflow). The existing post-cell `evict` now uses the same function.
