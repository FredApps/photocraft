## Pinned upstream reproduction and regression specification

The following is source material from the approved PR, not a record of testing this combined build. Test the stated scenario, values and regression names in addition to the procedure above.

Closes #7668, and fixes two more of the same kind that it turned up.

Crystallize is mapped with one field:

```rust
ev!("Crst", "crystallize", "Crystallize", "filter.pixelate.crystallize", &[F("ClSz", "cellSize", Kind::Long)]),
```

while the command takes `{"cellSize":3..300=10,"seed":u32=0}`. Photoshop's `Crst` descriptor has nowhere to put a seed, so `seed: 37` was dropped on export and replay seeded from 0 — a different pattern, with `skipped` empty and nothing in the file to say so. The report measures 583 differing colour components at every bit depth.

Auditing every mapped event against the params its command accepts turned up two more:

| step | silently dropped | what replay does instead |
| --- | --- | --- |
| `filter.pixelate.crystallize` | `seed` | seeds from 0 (#7668) |
| `filter.blur.radialBlur` | `centerX`, `centerY` | spins or zooms about the middle |
| `filter.other.minimum` / `.maximum` | `preserve` | keeps squareness |

(`layer.flattenImage`, `tools.swapColors` and `filter.blur.blur` also take params the event has no field for, but those are targets and selectors rather than settings that change the pixels, so they are left alone.)

### What changed

A table of the settings a mapped event cannot hold, with the value the event plays as:

```rust
const UNHOLDABLE: &[(&str, &[(&str, &str)])] = &[
    ("filter.pixelate.crystallize", &[("seed", "0")]),
    ("filter.blur.radialBlur", &[("centerX", "0.5"), ("centerY", "0.5")]),
    ("filter.other.minimum", &[("preserve", "squareness")]),
    ("filter.other.maximum", &[("preserve", "squareness")]),
];
```

A step that leaves such a setting at the value the event plays as exports exactly as before. A step that sets something else is refused: strict export names it, `skipUnsupported: true` leaves it out and reports it. That is the path `pixel_target` already takes for a filter aimed at a mask, "no field for a mask … so such a step can't be exported faithfully".

What this deliberately does **not** do is invent descriptor keys. I have no Photoshop to read a real `.atn` with, so writing a guessed `FlRs` into `Crst` or a `Cntr` into `RdlB` would be a clean-room violation and could make the file wrong in Photoshop as well as here. If you can confirm those keys from a Photoshop-written file, preserving the settings is strictly better than refusing them and I will follow up.
