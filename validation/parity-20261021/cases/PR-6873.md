Fixes #6752.

## Cause

`photocraft-heif` only read the `colr` **ICC** profile (`icc_for_item`). The `nclx` box was read by heic-rs, which applies its matrix and range when converting YCbCr to RGB, but its **primaries and transfer characteristics** were never passed on. A 10-bit HEIC tagged BT.2020 + ARIB STD-B67 (HLG) therefore opened as if its HLG-encoded BT.2020 values were sRGB: too bright and desaturated/shifted.

## Fix

- `photocraft-heif`: `Decoded::nclx` (primaries, transfer, matrix, full-range), inherited from the grid tiles like the ICC profile already is.
- `photocraft-codecs`: `Image::cicp` plus a small `cicp` module with the BT.2100 transfer functions. A PQ or HLG image is decoded to **linear light in a 32-bit float image**: HLG inverse OETF, then the OOTF for a 1000 cd/m² display (system gamma 1.2, luminance weights of the declared primaries), scaled so BT.2408's 203 cd/m² diffuse white is 1.0. PQ uses the ST 2084 EOTF on the same scale. The memory limit is checked again for the float image.
- `photocraft-cms`: `builtin::cicp_rgb(primaries, transfer, linear)` builds the profile for an H.273 description (BT.709 / BT.2020 / P3-D65 primaries; sRGB, BT.709, linear, gamma 2.2/2.8 curves), reusing the built-ins where they match.
- `photocraft-io`: a HEIF with no ICC profile gets that profile: linear BT.2020 for the HLG case, Display P3 / Rec. 2020 for SDR P3 / BT.2020 files. BT.709/sRGB SDR files stay untagged, as before.

**Why linear 32-bit float rather than tone-mapping to 16-bit:** PQ and HLG can't be an ICC tone curve, and the import path already supports 32-bit float with a linear profile (that is how OpenEXR and Radiance HDR open). So no new tone-mapping curve had to be chosen, and highlights above diffuse white are kept (values up to 1000/203 ≈ 4.9 for HLG) the way Photoshop holds HDR. Display and 8/16-bit conversion then go through the normal colour-managed path.

Out of scope (open PRs): matrix/range when the description is only in the HEVC VUI or only on grid tiles (#6089, #2354). An HLG file whose `nclx` is only in the VUI (no `colr` box) is not covered by this change.

## Tests

- `heif`: `nclx` parsed from hand-built `colr` boxes on a coded picture, and inherited by a grid from its tile; an ICC-only file has no `nclx`.
- `codecs::cicp`: HLG inverse OETF segment join (E' 0.5 → 1/12) and BT.2100/BT.2408 reference points (75 % HLG → 203 cd/m² = 1.0, peak → 1000/203, 50 % → 50.7 cd/m²), PQ (0.5807 → 203 cd/m², 1.0 → 10000/203), hue kept, NaN/inf/negative are safe; `linearize` gives F32, keeps alpha, drops the encoded ICC; SDR input is returned unchanged.
- `cms`: CICP → built-in mapping, linear BT.2020 colorants/curve and a valid ICC encoding; HLG/PQ without linear and unknown primaries are `None`.
- `io`: HLG BT.2020 (and unspecified primaries) is tagged linear BT.2020; BT.709/sRGB `nclx` stays untagged; P3 is tagged Display P3.
