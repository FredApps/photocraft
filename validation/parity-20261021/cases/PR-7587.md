## Root cause

An imported Photoshop action step **Close** with **Save: Yes** plays as two steps: `file.save {}` then `file.close {}`. Neither step names a document, so each one acts on whichever document is active when it runs. If a Save Document script event (`saveDocument` hook) closes document A during the save, the next step, `file.close {}`, closes whatever document is active then. In the issue's steps that is the unrelated dirty document B, so its unsaved changes are lost.

## Fix

- `crates/engine/src/actions_cmds.rs`: new helper `save_target_closed(session, id, target)`. For a played save step (`file.save`, `file.saveAs`, `file.saveACopy`), it reports a failure when the document that was active when the step started is no longer open.
- `crates/ui-egui/src/actions.rs`: shell playback notes the active document before each step. After a save step, it calls the helper. If the saved document is gone, playback stops at that step with a clear error ("the document was closed during the save (by a Save Document script event); playback stopped so later steps don't act on another document"), so no later step runs on B.

The check sits in `ui-egui` because the desktop shell runs the playback loop that performs saves.

Behaviour change: any action whose save step is followed by more steps now stops if a Save Document script event closes the saved document. Before, those later steps silently ran on another document.

## Testing

- New test `actions::tests::save_hook_closing_the_target_stops_an_imported_close_with_save`. It imports a real one-step `.atn` with Close / Save: Yes, then plays it with three Save Document hooks: none, activate B, and close.
