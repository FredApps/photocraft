Fixes #7238

## Cause
`replayable` let only `actions.play` through among `actions.*` ids, so the journaled `actions.conditional` entry was never recorded. When no branch ran, nothing went into the action. When a branch ran, only the nested `actions.play` of that branch was recorded and the predicate was lost (#7198).

## Fix
`replayable` now also accepts `actions.conditional`. `Session::execute` already pauses recording during a replayable command and drops the nested journal entries it produces, so the Conditional is recorded as one step with its original params, and playback evaluates the predicate again on the current document.

## Verified
- Regression tests `recording_a_conditional_keeps_the_step_when_no_branch_runs`, `recording_a_conditional_keeps_the_predicate_when_a_branch_runs`: fail on `main` without the fix and pass with it (`cargo test -p photocraft-engine --lib recording_a_conditional`).
- `cargo xtask ci` passes.

## Not changed
The Conditional command itself, the playback code and how the Actions panel shows Conditional steps are unchanged.
