Fixes #7092. Typing in a type layer no longer clones the whole document on every keystroke and pointer move.

### Root cause
`type_cmds::refresh` reads only the document's resolution and pixel format, but it took `&Document`. Every call site that holds the layer mutably had to clone the whole document to pass it: 15 of them across `type_cmds`, `type_extra_cmds`, `type_spell_cmds`, `type_styles_cmds`, `variables_cmds`, `warp_cmds` and `edit_menu_cmds`. `with_text_layer` (behind `type.edit`) and `with_text` also handed that copy to their closures, but every closure reads only `resolution_dpi` from it.

### Fix
- New `type_cmds::refresh_at(dpi, format, t)`. `refresh(doc, t)` stays as a wrapper, so callers that already hold the document (ui-egui, `canvas_geom`, `transform_cmds`, open PRs) don't change.
- The 15 sites read `(doc.resolution_dpi, doc.pixel_format())` before borrowing the layer, instead of cloning.
- `with_text_layer` and `with_text` pass their closures the resolution instead of a document copy. `type_extra_cmds` gets `layout_at(dpi, t)` next to `layout(doc, t)` for those closures.
- Two clones stay because they're used for more than `refresh`: Convert to Shape (`text_path`, `refresh_shape`) and the warp command's `refresh_text`.

### Numbers
`type.edit` on a 6000 × 4000 document with filled raster layers and a two-letter type layer, alternating the text, median of 300 edits. Release build, Intel Core Ultra X7 358H, Linux, with another job keeping all cores busy (main and this PR ran back to back).

| Layers | `Document::clone` | `type.edit` main | `type.edit` this PR |
|---|---:|---:|---:|
| 60 | 0.26 ms | 5.60 ms | 5.14 ms |
| 20 | 0.09 ms | 4.33 ms | 3.90 ms |

The saving is a little more than one clone, because the copy also had to be dropped. On a big paragraph the render dominates (#7032), so this matters most for small edits and many-layer documents.
