## What

Adds `crates/engine/src/param_schema.rs`: a typed description of a Command's input parameters.

- `Param { key, kind, optional, unit, default }` with a `Kind` enum covering the shapes the registry's `params` strings express today — bounded ranges (int/float), bool, text, choice lists, color, JSON, nested objects/arrays to the depth a doc describes, `Alt` unions, and a verbatim `Free` word for unbounded type words (`id`, `index`).
- `Unit` as a field (only the four that occur as value types: `px`, `pt`, `%`, `deg`) and `Default` incl. `Symbol` for UI-resolved defaults (`=foreground`, `=bottom selected`) the engine must not interpret.
- `UNIVERSAL` — one canonical list of keys every command accepts (`coalesce`, `target`, `layer`, `channel`), instead of today's three disagreeing hand-maintained versions of it.
- A renderer producing the agent/human Display string in the documented `{"radius":0.1..1000=1}` format (`docs/control-protocol.md`) **from** the schema, so the published string can be derived from one description instead of maintained beside it.

Pure addition: nothing reads the module yet, no dispatch/UI/file behavior changes, `std`-only, engine-side (L5), wasm-clean.

## Why

Motivated by #7596 (unknown parameter keys silently succeed), #7597 (parameter ranges kept in three hand-synced copies that demonstrably drift) and #7598 (the two hand-written parsers of the params string silently corrupt valid grammar — e.g. `0.5..5000 px?` loses its maximum). All three reduce to the same root: a command's parameter description is prose, re-parsed differently by each reader. This PR makes that description data, with the rendering contract pinned by tests; nothing else changes.

## Tests

8 golden tests over the documented grammar: ranges with defaults (int/float, negative bounds), choice lists with/without defaults, bool defaults, units and optional markers (`"size":0.5..5000 px?`), nested objects (`{"in":0..255,…}`), arrays, `Alt` unions (`"pixels"|"mask"|{"channel":i}`), symbolic defaults, the open-ended marker, prose-notes pass-through, and universal-key merge/dedup.
